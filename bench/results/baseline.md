## 不对称：签名担保不了「真」

签名 Merkle 日志的核验链是「验签 → 验日志包含 → **重跑 `J(π,T)`**」。前两步只需要公开数据；**第三步需要 `π` 与 `T` 的明文**，这不是实现缺陷，是签名范式的结构性后果 —— 签名只把「谁说了这句话」绑到字节上，不把「这句话是真的」绑到任何东西上。下面每一条都是**跑出来的断言**（全绿才算跑完）：

| 机器校验的断言 | 结果 | 说明 |
|---|---|---|
| 公开路径验签 + 验包含都通过 | ✅ | 公开数据不是废的：签名与日志包含都由它核 |
| 公开路径回答不了 passed（None / honest=False） | ✅ | 签名不担保内容为真，只担保『谁说了』 |
| 拿公开结果当诚实核验 ⇒ 抛 BaselineError | ✅ | require_honest() 把这个误用变成异常 |
| 缺 π 或 T ⇒ 重跑路径拒绝（fail loud） | ✅ | 不静默降级成『只验签』 |
| 签名有效但内容为假 ⇒ 公开路径全绿、重跑才抓住 | ✅ | 公开路径看到的是一份『合格』证书；真值只有重跑 J(π,T) 才知道 |
| 给了 π 与 T ⇒ 重跑确认 passed=True | ✅ | 这一步是 ZK 从验证者手里**拿走**的那一步 |

最后一行值得单独读：**同一把钥签一份内容为假的证书，公开路径照样全绿**—— 因为它看到的是一份签名有效、包含有效的『合格』证书；真值只有重跑 `J(π,T)` 才知道。ZK 换来的恰恰是把这一步从验证者手里拿走。

## 属性对照

| property | signed-Merkle baseline | PoP (ZK) |
|---|---|---|
| trust root（信任根基） | Ed25519 网关密钥 —— 信任落在**持钥的网关**上（密钥泄了就没有不可否认性） | 密码学 / 无硬件信任：只需 vkey，无需信任某台机器或某把钥不泄 |
| 验证者需要 `T` 明文？ | **需要** —— 不重跑 `J(π,T)` 就无法确认 `passed`（本表量到的那条路） | 不需要 —— 判定在电路内，响应可只以承诺出现 |
| 验证者需要 `π` 明文？ | **需要** —— 重跑要用同一份策略；签名要求签名者公开判定依据 | 不需要 —— 只需 `policy_hash` 与 vkey |
| 响应隐私 | 无 —— `T` 要交到验证者手里 | 有（私有模式：证书里只有 `response_commitment` / `response_binding`） |
| 策略隐私 | 无 —— 策略保密下签名范式直接失效（验证者无从重算） | 有 —— 策略进电路作私有见证 |
| 不可否认性 | **相同** —— Ed25519 与 ZK 路径同源，这条基线**不更弱**（诚实的一行） | **相同** —— 同样是 Ed25519 签名 / vkey 绑定，本行不为 ZK 记分 |
| 成本 | 本表实测：签名 0.132 ms · 公开核验 0.322 ms · 重跑核验 0.772 ms · 证书 648 B · 证明 761 B（n=500） | **n/a — 见 WP1 / `bench/results/proofs.md`（ZK 成本待 WP1 的云机重跑后补）** |
