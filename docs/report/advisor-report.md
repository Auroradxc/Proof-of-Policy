## 1. 完整流程：从策略编写到第三方验证

### 1.1 八环流水线

| # | 环节 | 输入 | 产物 | 谁验它 |
|---|---|---|---|---|
| 1 | **策略编写** | 人写的 JSON 策略包 | `policy_packs/*.json`（8 类规则） | 编译器语法闸门 |
| 2 | **编译** | 策略包 | `ConstraintSpec`（JSON，**层间唯一契约**） | Python 参考判定 vs 电路判定对拍 |
| 3 | **运行时插桩** | 真实 agent 会话（LangChain / LangGraph / MCP） | 回调事件流 | 适配器单测 |
| 4 | **轨迹绑定** | 每次工具调用 | **网关签发的回执链** `tool receipts` + 会话末端承诺 `ToolSeal` | 链下 Ed25519 验签 + 电路结构校验 |
| 5 | **证书** | 判定结果 | **DSSE 信封 + Ed25519 签名**的合规证书 | 第三方复算签名/指纹/绑定 |
| 6 | **锚定** | 证书摘要 | 锚定账本（文件台账 / 本地 Anvil 链） | 摘要比对 + 反例对照 |
| 7 | **ZK 证明** | `T` + 策略 + 回执链 | SP1 证明（3 个 guest 程序） | SP1 verifier 或 `pop-verify`（免构造证明器） |
| 8 | **第三方验证** | **只有公开产物** | `RESULT: PASS/FAIL` 逐项卡片 | 独立脚本，不复用出证方的任何代码路径 |

一句话读法：**1–2 把「策略」变成「约束」，3–5 把「一次会话」变成「可核验的证书」，6–8 把「我说的」变成「你能自己算的」。**

### 1.2 两个层间合同（导师最值得看的两处）

**① `ConstraintSpec`（第 2 环产物）** —— Python 参考层与 Rust/SP1 电路层之间**只签这一份合同**。
两层各自实现判定，用**跨语言对拍**钉住逐点一致（CI 的 `rust` job）。

**② 证书信封（第 5 环产物）** —— 标准 **DSSE** 信封，载荷字段（下为一次真实运行的原样结构，已截断长哈希）：

```jsonc
{
  "cert_version": "v1",
  "mode": "tool-call",              // public / private / stream / tool-call
  "policy": {"id": "agent-tool-v1", "version": "0.1.0"},
  "policy_hash": "68a1961f…",       // 策略指纹：换一个字符就不同
  "outcome": {                      // ★ 证明公开值的镜像 —— 电路里有的字段才在这里
    "passed": true, "violations": [], "trace_root": "9dc153f7…", "zk": true
  },
  "trace_seal": {"count": 1, "trace_root": "9dc153f7…", "ts": "…",
                 "keyid": "ed25519:40ad5f32…", "sig": "6d3355a2…"},  // ★ 顶层旁证，不进 outcome
  "binding": {"proof_mode": "unproven", "vkey_hash": "unproven",
              "proof_sha256": null, "public_values_sha256": null},
  "ai_act": {"art12_record_keeping": {"anchored": true, "per_call_record": true,
                                      "policy_hash_bound": true, "response_bound": false},
             "art13_transparency": {"mode": "tool-call", "outcome_disclosed": true,
                                    "policy_disclosed": true}},
  "ts": "2026-09-18T03:55:24Z"
}
```

两处设计要点，答辩时会被问到：

- **`outcome` 只放「电路公开值的镜像」**。证据、封装、EU AI Act 标注都在**顶层**，因为电路里没有这些字段 ——
  把链下东西塞进 `outcome` 会让「证明过的」与「没证明的」看起来一样。
  字段集合**随模式变化**：公开模式是 `{passed, violations, policy_hash, response_binding, trace_root, delegated}`，
  工具调用模式是 `{passed, violations, trace_root, zk}`（上例），私有模式换成承诺与脱敏见证。
- **`binding.proof_mode` 从一开始就写明这是不是证明**。宿主校验路径签出来的是 `unproven`，
  没有「看起来验过了」的空间；真要证明时它是 `core`/`compressed`（也可能是 `groth16`/`plonk`），
  并带 `vkey_hash` 与证明摘要。

### 1.2b 三个哈希的定义（都在域分隔符下，逐字节钉死）

| 名字 | 定义 | 作用 |
|---|---|---|
| `response_binding` | `SHA256("pop-bind-v1" ‖ u32be(len(nonce)) ‖ nonce ‖ T)` | 把结论**绑到这一条具体响应**上，防调包 |
| `trace_root` | 回执链**末条回执**的 `receipt_digest`（链从 `TRACE_GENESIS` 起，域分隔 `"pop-trace-v1"`） | 绑定整条工具轨迹 |
| `policy_hash` | 策略包规范化 JSON 的 `sha256`（编译产物 `ConstraintSpec.sha256`） | 绑定策略版本 |

**域分隔符是「同一哈希在两个用途下不互相冒充」的全部实现**，写错一个字符的后果不是报错，
而是两侧各自自洽、合起来对不上 —— 所以有一条测试**逐字节**比对四个域
（`pop-trace-v1` / `pop-bind-v1` / `pop-infer-v1` / `pop-session-node-v1`）在 Python 与 Rust 两侧的字面量，
且它**不需要 Rust 工具链**（比的是声明的字面量），因此进得了零依赖的 CI 通道。

## 3. 设计思路

### 3.1 问题与威胁模型

要解决的问题：**「agent 的合规声明无法被独立核验」** —— 日志可伪造、护栏「跑过了」不等于「合规了」、
而内容隐私又要求不留明文。

参与者与信任假设（`docs/security-model.md`）：

| 角色 | 信任 |
|---|---|
| **证明者 = agent 运营方** | **不可信（核心对手）**：持 `T` 与回执链，可自选要证明什么 |
| 工具网关 | **显式信任**：持 Ed25519 私钥，每次工具调用执行后签发回执 |
| 验证者 | 诚实：只持公开产物，可出 nonce、独立重算 |
| 策略作者 / 账本 | 诚实 / 弱信任（仅要求不可篡改） |

对手能力：可任意次调用出证接口、任意索取 nonce、可**自适应地**请求工具调用以拿到任意消息的合法回执签名、
可读一切公开产物；**不持有**网关私钥、出证方私钥，也无 zkVM 健全性突破口。

### 3.2 为什么不用 TEE

| | TEE 路线（Proof-of-Guardrail 等） | **本项目** |
|---|---|---|
| 证的是什么 | 护栏代码**执行过**（执行 ≠ 合规，作者自述） | **性质成立**：`T` 满足 `π` |
| 信任根基 | 硬件厂商 | **密码学**（zkVM 健全性 + 哈希） |
| 代价 | 约 34% 延迟 + 硬件依赖 | 证明时间（分钟级），纯 CPU |
| 内容隐私 | 需读输入输出 | 双模式：承诺 / 选择性披露 + 带证明脱敏（**上界见 §7**） |

四象限定位（`docs/quadrant.md`）：「**密码学健全 × 证性质**」这一格此前为空，PoP 落在该格。

### 3.3 四条核心取舍

1. **只证「响应满足策略」**，不证推理正确性 —— 后者另开一条（§4.5 的组合证明），且当前只是**代理**。
2. **8 类规则里 7 类进电路**，第 8 类（学习型语义规则）**不进电路**，改为**陪伴证明 + 验证方合取**。
3. **链上只锚定证书摘要**，证明本身按需出、按需验 —— 因为出证比验证贵 4 个数量级。
4. **两个时间尺度拆成两条接口**（在线毫秒判定 / 离线分钟级证明），且在线那侧的证书**一开始就写明自己不是证明**。

### 3.4 明确**不声称**的东西（答辩防线）

| 不声称 | 为什么 |
|---|---|
| 「响应内容不可恢复」 | 只保证「公开值不含明文」；低熵 `T` 可枚举猜测-验证，且 SP1 `core`/`compressed` 证明**非零知识**（自查明文 + 源码审计，`docs/sp1-zk-audit.md`） |
| 「电路内验了网关签名」 | 回执链的**结构**在电路内，**签名**在链下 Ed25519 验 —— 论文明确不宣称后者 |
| 「网关不会作恶」 | 假设 A4，作者自述这是**最弱的一环** |
| 「证明了真实 LLM 跑过」 | 不证；组合证明里的推理半是**确定性 MLP 代理**（其源码不可得） |
| 「token 数是真实分词」 | 电路内按固定空白字节集自算，不假称任何真实分词器 |
| 「覆盖训练数据 / 模型卡」 | 超出系统范围（EU AI Act Art.11 不在映射内） |

## 4. 设计细节

### 4.1 策略 DSL → `ConstraintSpec`

- **规则 8 类**（`policydsl/core/model.py` 顶部即权威清单）：
  `keyword_block`（关键词）/ `normalized_keyword_block`（**先按约束自带折叠表**把同形异义字、
  零宽字符、全角折叠后再判，折叠在电路内完成）/ `length_bound` / `pattern_block`（正则，含 PII）/
  `format_check`（json/int/float）/ `tool_arg_guard`（工具参数禁字段）/ `budget_bound`（累计预算）/
  `semantic_bound`（学习型，**由陪伴证明承担，电路只登记委托**）。
- 编译入口 `policydsl.core.compile.compile_policy`，产物 `ConstraintSpec`（`spec_version` / `policy_id` /
  `policy_version` / `semantic` / `constraints[]` / `sha256`）。`sha256` 只作用于**规范化 JSON 文本**
  （`description` 不进哈希、`semantic` 进）—— 它是 `policy_hash` 的来源，也是「三方比对」的基础：
  出证方、验证方、电路公开值三方现场重编译必须得到同一个值。
- **可序列化 NFA 契约**：正则子集经 Thompson 构造编译成同一台 NFA，判定用 **Pike VM**（单趟、状态并集推进），
  Python 与 zkVM 两侧实现同一台机器。为什么强调：按起点重跑的朴素做法**可被对抗输入拖入二次复杂度**（消融见 §5.3）。
- 编译含 **fail-fast 语法子集闸门**：编译期就拒绝电路表达不了的正则，而不是等到出证才炸。

### 4.2 轨迹绑定：回执链 + 会话末端承诺

工具轨迹**不再由 agent 自报** `tool_calls`，而是由**工具网关**在调用执行后签发**回执链**：

- 每条回执 `ToolReceipt{seq, tool, args, result_digest, ts, prev, keyid, sig}`，
  `prev` 把前一条的回执摘要串进来 —— 于是「链」这个结构本身就是承诺；
- 链的**结构**由电路保证：删一条 / 换一条 / 重排序 → `trace_unbound` **fail-closed**；
- **签发者身份**由链下 Ed25519 验签 + 公开值 `trace_root` 承担（电路内**不**验签名，见 §3.4）；
- **截尾**（整条删掉链尾那条违规回执）由网关的**会话末端承诺** `trace_seal{count, trace_root, ts, keyid, sig}` 拦 ——
  放在载荷**顶层**，因为它不在电路的公开值里；
- 验证方**必须给 `--gateway-key`** 才核得了签名，否则脚本如实标注「签名未验」。

### 4.3 双隐私模式

同一条响应、同一条策略、同一个 nonce，两种模式各出一张证书，**判定结果必须相同**（脚本自己断言）：

| 验证方能看到 | 公开模式 | 私有模式 |
|---|---|---|
| 结论 / 策略指纹 | 相同 | 相同 |
| 命中了哪几条规则 | 相同 | 相同 |
| 每条规则的证据 | **明文**（如命中词 `exploit`、连密钥正则一起照抄） | **证据承诺**（哈希） |
| 响应本身的承诺 | —（该模式不承诺 `T`） | 有 |
| 脱敏见证 | — | `mask_count` / `mask_covered` |

私有模式的出口不是「涂黑」，而是**证据选择性开示**：开示一件证据时，该件必须与证书里那条承诺**逐条相符**，篡改一件即被拒。

### 4.4 证书：DSSE 信封 + 双层载荷

见 §1.2。要点：**`outcome` = 电路公开值的镜像**（没进电路的字段一律不进 `outcome`），
其余（`trace_seal`、`ai_act`、`binding`、`error` 块）都在**顶层**。
三种证明模式在字段上**当场可辨**：`unproven` / `core` / `compressed`。

### 4.5 三个 guest 与键分离

| guest | 证什么 | 为什么必须独立 |
|---|---|---|
| `pop-program` | 策略合规 | 基准 |
| `pop-infer` | 推理完整性（**代理 MLP**） | 与策略半**必须不同程序**（键分离），否则「这份证明属于哪一半」无从判断 |
| `pop-session` | 一组证书的跨证书一致性（`policy_hash` 全同 / 链无缝 / 覆盖完整轨迹） | 与前两域 vkey 不同 |

`Compose = (推理完整性 ∧ 策略合规)` 合成一张组合证书，回答「**这条 `T` 是被那个模型算出来的吗**」——
这个问题策略合规本身不覆盖。

### 4.6 服务化

两个阶段的时间尺度差 **4 个数量级**（宿主判定毫秒级 vs SP1 core 证明 ~2.5 分钟），所以拆两条接口：

- `POST /v1/check`：在线，毫秒级，证书如实标 `unproven`；
- `POST /v1/attest` → 轮询：离线，真证明；两段传同一 nonce 时绑的是同一条 `T`。
- **并发上限是硬事实**：~10.15 GiB 是证明的固定地板，12 GB 机器同时只能跑一个 → 默认 `concurrency=1`，
  超出**排队**（队列满返 429，而不是收下之后 OOM）；**不可出证的策略当场拒**（返 400，`serviceable: false`）。

## 5. 创新点

### 5.1 空位在哪

已有的四派各自不足：TEE 证明「护栏执行过」而**执行 ≠ 合规**；治理栈同样依赖 TEE 与厂商设施；
形式验证需要人工形式化且**对黑盒响应不适用**；ZK 正则/PII 只是**积木**而非系统。
「**通用策略 DSL → ZK 约束编译 + 无硬件信任 + 双隐私模式 + 形式化安全模型 + 开源**」的组合此前无人系统化。

### 5.2 四项贡献

1. **PoP 系统**：通用 DSL → ZK 判定 → 双隐私模式 → 合规证书的开源端到端实现（8 条支路）。
2. **可序列化 NFA 契约**：正则子集跨层（Python ↔ zkVM）一致，含 fail-fast 语法子集与 Pike VM 判定。
3. **形式化安全模型**：游戏 + 归约，含健全性 / 承诺式隐私 / 不可伪造 / 绑定 / 记录完整性，
   外加三条「推广到单条响应之外」的引理（L6 组合 / L8 跨证书 / L9 多证明者），**每条给出代码落点**。
4. **评测**：周期数矩阵、NFA 消融（含对抗输入下的二次退化）、真实证明时间/大小/内存、信任-成本四象限。

### 5.3 消融（这是最容易讲清「设计对不对」的一组数字）

病理输入（`a`×n 对正则 `a+b`）下朴素实现 vs Pike VM：

| n | Pike | 朴素 | 比值 |
|---:|---:|---:|---:|
| 100 | 643,894 | 12,382,720 | **19.2×** |
| 200 | 1,145,209 | 48,638,946 | **42.5×** |
| 400 | 2,143,617 | 193,207,130 | **90.1×** |

比值随 n **翻倍** ⇒ 朴素做法是 O(n²)、可被**对抗输入**拖垮，Pike 保持线性。这就是「默认必须用 Pike」的证据。

自然语言上两者只差 1.5–2.1× —— 所以**如果只测常规文本，会得出「随便哪种都行」的错误结论**。

### 5.4 与最贴近的同期工作（zkAgent, ePrint 2026/199）对标

| 维度 | 本项目 | zkAgent |
|---|---|---|
| 证明时间 | 118.9–172.5 s | 194.40 s / ~1069 s |
| 验证时间 | ~0.090 s | 0.42 s / 0.038 s |
| 证明大小 | ~2.7 MiB | ~96 MiB / 3.1 MiB |
| 硬件 | **24 核 / 12 GB** | 32 核 / **512 GB** |
| 内容隐私 | 承诺式（双模式 + 选择性开示） | 无 |

**口径很重要**：本项目**不主张「更快」**，主张的是「对『合规』这条义务，在不涉及模型的前提下以**同量级时间、
更小内存**完成，并补上承诺式隐私」。

## 6. 实用价值

### 6.1 定位

**离线审计 / 报送 / 批量合规核查**，不是实时护栏。取舍一句话：每次开销从「硬件延迟」变成「证明时间」，
换来**无硬件信任 + 内容隐私**。

### 6.2 EU AI Act 工程映射（**证书里就带着**）

映射不止写在文档里 —— 每张证书载荷里有一个 `ai_act` 块（见 §1.2），把义务**逐条落到具体字段**：

| 义务 | 落点 |
|---|---|
| Art.12 记录保存 | 每张证书 `cert_version`/`ts`；`policy_hash` + `binding{vkey_hash, proof_sha256, proof_mode}` 绑定策略版本与电路；`cert_digest` 入防篡改锚定账本；粒度为**单次响应 / 单次工具调用** |
| Art.13 透明性 | `mode` / `outcome` 告知内容是否公开、是否合规；验证方可独立复算；私有模式只公开承诺 |

> 文档明确标注这是**工程映射、非法律意见**；`training data / 模型卡`（Art.11）明确记为**超出范围**。

### 6.3 部署形态

- **审计路径免证明器**：`circuits/verifier`（`pop-verify`）让验证方**不需要构建 prover** 即可验证。
- **常驻服务**：`scripts/ops/proof_service.py`，两段接口 + 排队 + 满载 429（见 §4.6）。
- **链上锚定**：`contracts/Anchor.sol` + 本地 Anvil 一键端到端。合约只存
  `mapping(bytes32 digest => uint256 ts)`，`anchor()` 是 **first-write-wins**（重复锚定回滚），
  另有 `anchoredAt`/`anchoredBy`/`isAnchored` 与 `Anchored(digest, ts, by, seq)` 事件；ABI + bytecode 已入库，
  **部署不需要 solc**。
- **语义规则的成本**（ezkl 陪伴证明，离线批处理）：setup 48.2 s / 出证 **76.6 s（峰值 8.72 GiB，证明 40 KiB）** /
  验证 1.0 s —— 约 77 s/条响应，这也是它被定位成**离线审计**而不是实时护栏的直接原因。
- **接入现实框架**：LangChain / LangGraph / MCP 三个适配器已实测；接自己的框架只需实现
  `AgentMonitor.on_generate` / `on_tool_call` + 一会话一把 `ToolGateway`。

## 7. 还未解决的问题（如实清单）

按「影响 × 是否有出路」排。**先说结论**：真正挡住收尾的只有一条 —— **第 2 条的内存天花板**，
它的具体后果就是 §2.1 的 T1（租 ≥64 GB 云机出 groth16 证明 + 测通链上验证合约）。其余九条都是

| 1 | **私有模式的隐私上界** | 只保证「公开值不含明文」。**两个独立理由**：① SP1 `core`/`compressed` 非零知识（官方安全模型明文 + 本机源码审计）；② 更根本地，「响应绑定」与「内容隐藏」对**低熵 `T` 互斥** —— 公开值里的响应承诺可离线枚举猜测-验证，这与证明系统无关 | 要「不可恢复」需换零知识证明系统（如 groth16/plonk 隐藏见证），**本机内存不够、仅设计上可行未实测** |

## 8. 附录：导师可能追问的 8 个问题

| 问题 | 一句话备答 |
|---|---|
| 「你这个和 ZKML / zkAgent 有什么区别？」 | 它们证**模型算得对**，我们证**输出满足策略** —— 义务不同。zkAgent 覆盖推理完整性，代价是依赖模型；我们**不涉模型**，因此能在 24 核/12 GB 上以同量级时间出证。两者是互补的，我们的组合证明就是想把两者合起来（当前推理半是代理）。 |
| 「不用 TEE，那凭什么信？」 | 信的是**zkVM 的健全性 + 哈希**，不是硬件。网关仍需信任（假设 A4），这是模型里**最弱的一环**，已如实标注。 |
| 「零知识？那我把你的响应反推出来？」 | 反推不出**明文**，但**能对低熵文本做猜测-验证**。这条是我们自己查出来并写进标题与 README 的，不是被问出来的。要更强的保证得换证明系统。 |
| 「一次证明多少钱 / 多久？」 | 本机（24 核 / 11.7 GiB）：**118.9–172.5 s、2.7 MiB、峰值 ~10.4 GiB**；瓶颈是**内存不是 CPU**，固定地板 ~10.15 GiB。 |
| 「策略复杂了会不会爆？」 | 会，且有明确边界：成本由 **NFA 扫描 × 文本长度**主导，不由规则条数主导（一条 NFA 正则边际 ≈3,634 周期/字符，一条关键词 ≈31.6，差 **115 倍**）。可行域是「两级台阶」，3 条规则 × 200 字符在本机就 OOM。 |
| 「怎么保证你的判定和电路判定一致？」 | 两层各自实现 + **跨语言对拍**（CI 的 `rust` job 逐点比），且编译期有 fail-fast 语法子集闸门。 |
| 「工具调用是 agent 自报的吗？」 | 不是 —— 网关在调用**执行后**签发回执链，结构由电路保证（删/改/重排 → fail-closed），**截尾**由会话末端承诺拦。验签在链下，这条如实标注。 |
| 「论文投哪、现在什么状态？」 | `paper/proof-of-policy.tex` 结构完整（摘要 → 相关工作 → 威胁模型 → 系统 → 安全模型 L1–L9 → 实现 → 评测 7 节 → 局限 → 结论 → 复现附录），标注为**工作稿 Phase 6 / W8**；作者信息未填，投稿目标待定（CCS/USENIX/S&P/NDSS，退 PoPETs）。 |
