## 1. 任务目标

### 1.1 一句话目标

给定**公开策略 π** 与一条 agent 响应 `T`，产出一份**验证方自己算得出来**的证据：「`T` 满足 π」——
结论公开、违规内容不公开、**无硬件信任**。

要做到四件事：

| | 目标 | 落点 |
|---|---|---|
| ① | **可判定** | 把策略写成机器可判定的规则，编译成一个跨层契约（§4.2） |
| ② | **可证明** | 判定过程搬进 zkVM（SP1），产出证明而**不暴露响应**（§4.6） |
| ③ | **可核验** | 第三方**只用公开产物**就能复算，不需要信运营方（§3.1 第 8 环） |
| ④ | **可接入** | 接**真实** agent 框架，判的是真会话，不是 mock（§4.1） |

### 1.2 明确**不**做的事（答辩防线，详见 §2.5）

| 不做 | 说明 |
|---|---|
| **不证推理** | 不证「模型算得对」，也不证「这条 `T` 一定是那个 LLM 算出来的」（组合证明里的推理半是**代理 MLP**，如实标注） |
| **不碰权重** | 不涉及模型权重与训练过程 |
| **不做实时** | 出证按分钟计，定位是**离线审计 / 报送 / 批量核查** |
| **不声称全隐** | 「零知识」只到**策略零知识**：不保证响应内容不可恢复 |

### 1.3 交付判据（怎么算做完了）

| 判据 | 形态 | 现状 |
|---|---|---|
| 端到端支路可跑 | `bash scripts/demo/demo_all.sh` 无 FAIL、SKIP 集合不变 | ✅ 8/8 通过 |
| 第三方能独立复算 | `verify_session.py` 只用公开产物 → `RESULT: PASS` | ✅ 10/10 检查 |
| 两层判定一致 | 跨语言对拍 Python↔Rust 逐点相同（CI `rust` job） | ✅ 19/19 |
| 真出证能过 | `regression_prove.py --label …` 出证腿 + 验证腿双 PASS | ✅ 5 次留痕 |
| 换证明模式也能出证 | `compressed`/`groth16`/`plonk` 真证明 + 链上验证合约 | ⚠️ 卡在本机内存（T1，§6.1） |

## 2. 设计思路与实现

### 2.1 问题与威胁模型

要解决的问题：**「agent 的合规声明无法被独立核验」** —— 日志可伪造、护栏「跑过了」不等于「合规了」、
而内容隐私又要求不留明文。

参与者与信任假设（`docs/security-model.md`）：

| 角色 | 信任 |
|---|---|
| **证明者 = agent 运营方** | **不可信（核心对手）**：持 `T` 与回执链，可自选要证明什么 |
| 工具网关 | **显式信任**：持 Ed25519 私钥，每次工具调用执行后签发回执 |
| 验证者 | 诚实：只持公开产物，可出 nonce、独立重算 |
| 策略作者 / 账本 | 诚实 / 弱信任（仅要求不可篡改） |

对手能力：可任意次调用出证接口、任意索取 nonce、可**自适应地**请求工具调用以拿到任意消息的合法回执签名、
可读一切公开产物；**不持有**网关私钥、出证方私钥，也无 zkVM 健全性突破口。

### 2.2 为什么不用 TEE

| | TEE 路线（Proof-of-Guardrail 等） | **本项目** |
|---|---|---|
| 证的是什么 | 护栏代码**执行过**（**执行 ≠ 合规**，作者自述） | **性质成立**：`T` 满足 `π` |
| 信任根基 | 硬件厂商 | **密码学**（zkVM 健全性 + 哈希） |
| 代价 | 约 34% 延迟 + 硬件依赖 | 证明时间（分钟级），纯 CPU |
| 内容隐私 | 需读输入输出 | 双模式：承诺 / 选择性披露 + 带证明脱敏（**上界见 §9 第 1 条**） |

四象限定位（`docs/quadrant.md`）：纵轴＝证**性质成立**还是**护栏执行过**，横轴＝信任来自**密码学**还是
**硬件/人工**；「**密码学健全 × 证性质**」这一格此前为空，PoP 落在该格。

### 2.3 四条核心取舍

1. **证「性质」而不是「执行」** —— 证明的公开值是 `passed / violations / policy_hash…`，不是「某段代码跑过」的日志。
2. **判「整条链」而不是「这一条」** —— 工具证书的 `passed` 含义是「会话进行到这次调用为止一直合规」。
   保守取侧：一张写 `passed=True` 的证书绝不该出现在一条脏轨迹上。
3. **判不了就出证判失败，不是沉默** —— fail-closed：判定做不了 ⇒ 仍为同一条回执签一张 `passed=false` 的证书
   + 顶层 `judgment` 块。沉默与「干净」在产物上同形，那正是要消灭的歧义。
4. **层间只签一份合同** —— Python 参考层与 Rust 电路层之间只有 `ConstraintSpec` 一个接口。

### 2.4 系统框架图

六层结构：**出证侧五层 + 验证侧一层**。自上而下就是一次出证的真实顺序。

```
   策略层     policy_packs/*.json ──▶ core/compile.py ──▶ semantic/（ezkl 旁路）
      │       人写 JSON 策略包 · 8 类规则 · 编译期 fail-fast 语法子集闸门
      │
      ▼  编译产出（层间唯一契约）
   契约层     ConstraintSpec{spec_version, policy_id, policy_version, semantic, constraints[], sha256}
      │       policy_hash ← 出证方 · 验证方 · 电路公开值：三方现场重编译必须同值
      │       ┈┈┈┈┈┈┈┈┈┈┈┈┈ 这条合同**同时约束验证层**（验证方拿着公开产物自己重编译）┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈
      │
      ▼
   运行时层   真实 agent ──▶ 适配器 ×4 ──▶ AgentMonitor ──▶ ToolGateway
      │       LangChain/LangGraph/MCP/通用   两个钩子：判定→出证   调用**执行后**签发回执
      │
      ▼
   产物层     cert.json（DSSE + Ed25519） · 回执链 + ToolSeal · ledger.jsonl · Anchor.sol 摘要上链
      │
      ▼
   证明层     pop-program（域 policy） · pop-infer（域 infer） · pop-session（域 session） · ezkl 陪伴证明
      │
      ▼
   验证层     verify_cert.py（逐项） · verify_session.py（会话级 10 项） · pop-verify（免证明器）
```

怎么读这张图：**同一行里的方框是并列关系，箭头是数据流**；蓝色那条（上图中的 `┈┈`）是全系统最要紧的一处 ——
`ConstraintSpec` 同时约束两端，验证方不是「相信出证方算对了」，而是**自己再算一遍**，比 `policy_hash`。

### 2.5 明确**不声称**的东西

| 不声称 | 为什么 |
|---|---|
| 「响应内容不可恢复」 | 只保证「公开值不含明文」；低熵 `T` 可枚举猜测-验证，且 SP1 `core`/`compressed` 证明**非零知识**（自查明文 + 源码审计，`docs/sp1-zk-audit.md`） |
| 「电路内验了网关签名」 | 回执链的**结构**在电路内，**签名**在链下 Ed25519 验 —— 论文明确不宣称后者 |
| 「网关不会作恶」 | 假设 A4，作者自述这是**最弱的一环** |
| 「证明了真实 LLM 跑过」 | 不证；组合证明里的推理半是**确定性 MLP 代理**（其源码不可得） |
| 「token 数是真实分词」 | 电路内按固定空白字节集自算，不假称任何真实分词器 |
| 「覆盖训练数据 / 模型卡」 | 超出系统范围（EU AI Act Art.11 不在映射内） |

## 3. 系统实现流程

### 3.1 八环流水线

| # | 环节 | 输入 | 产物 | 谁验它 |
|---|---|---|---|---|
| 1 | **策略编写** | 人写的 JSON 策略包 | `policy_packs/*.json`（8 类规则） | 编译器语法闸门 |
| 2 | **编译** | 策略包 | `ConstraintSpec`（JSON，**层间唯一契约**） | Python 参考判定 vs 电路判定对拍 |
| 3 | **运行时插桩** | 真实 agent 会话（LangChain / LangGraph / MCP） | 回调事件流 | 适配器单测 |
| 4 | **轨迹绑定** | 每次工具调用 | **网关签发的回执链** + 会话末端承诺 `ToolSeal` | 链下 Ed25519 验签 + 电路结构校验 |
| 5 | **证书** | 判定结果 | **DSSE 信封 + Ed25519 签名**的合规证书 | 第三方复算签名/指纹/绑定 |
| 6 | **锚定** | 证书摘要 | 锚定账本（文件台账 / 本地 Anvil 链） | 摘要比对 + 反例对照 |
| 7 | **ZK 证明** | `T` + 策略 + 回执链 | SP1 证明（3 个 guest 程序） | SP1 verifier 或 `pop-verify`（免构造证明器） |
| 8 | **第三方验证** | **只有公开产物** | `RESULT: PASS/FAIL` 逐项卡片 | 独立脚本，不复用出证方的任何代码路径 |

一句话读法：**1–2 把「策略」变成「约束」，3–5 把「一次会话」变成「可核验的证书」，6–8 把「我说的」变成「你能自己算的」。**

### 3.2 三个哈希（都在域分隔符下，逐字节钉死）

| 名字 | 定义 | 作用 |
|---|---|---|
| `response_binding` | `SHA256("pop-bind-v1" ‖ u32be(len(nonce)) ‖ nonce ‖ T)` | 把结论**绑到这一条具体响应**上，防调包 |
| `trace_root` | 回执链**末条回执**的 `receipt_digest`（链从 `TRACE_GENESIS` 起，域分隔 `"pop-trace-v1"`） | 绑定整条工具轨迹 |
| `policy_hash` | 策略包规范化 JSON 的 `sha256`（编译产物 `ConstraintSpec.sha256`） | 绑定策略版本 |

**域分隔符是「同一哈希在两个用途下不互相冒充」的全部实现**，写错一个字符的后果不是报错，
而是两侧各自自洽、合起来对不上 —— 所以有一条测试**逐字节**比对四个域
（`pop-trace-v1` / `pop-bind-v1` / `pop-infer-v1` / `pop-session-node-v1`）在 Python 与 Rust 两侧的字面量，
且它**不需要 Rust 工具链**（比的是声明的字面量），因此进得了零依赖的 CI 通道。

| # | 支路 | 驱动 | 状态 |
|---|---|---|---|

## 4. 功能实现与模块耦合

### 4.1 分层与依赖方向

依赖只许朝一个方向：**`core` 谁也不认识**。

| 层 | 目录 | 职责 | 它依赖谁 |
|---|---|---|---|
| ⑤ 脚本 / 服务 | `scripts/` | 八条支路的驱动、证明服务、回归编排 | 以下全部 |
| ④ 适配器 | `policydsl/adapters/` | 把真实框架的回调转成判定与出证 | `evidence` · `core` |
| ③ 证据 | `policydsl/evidence/` | 证书 / 回执链 / 密钥 / 账本 / 隐私承诺 | `core` · 密码学库 |
| ② 核心 | `policydsl/core/` | 策略模型、编译器、判定引擎、正则子集 | **标准库** |
| ① 电路 | `circuits/` | 三个 SP1 guest + NFA 的 Rust 实现 | 只吃 `ConstraintSpec` |

- **为什么这条最要紧**：`core` **零外部依赖** ⇒ 判定引擎在任何机器上都能跑，CI 的 `tests` job 因此不需要装任何东西，**判据只有一份**。
- **耦合是怎么被钉住的**：`tests/test_layering.py` 直接检查依赖方向；`test_frontdoor.py`、`test_doc_links.py`
  （47 份文档 / 291 条链接 / 悬空 0）各守一面。
- **唯一的跨语言耦合点**就是 `ConstraintSpec`。

### 4.2 两份层间合同

**① `ConstraintSpec`（第 2 环产物）** —— Python 参考层与 Rust/SP1 电路层之间**只签这一份合同**。
两层各自实现判定，用**跨语言对拍**钉住逐点一致（CI 的 `rust` job）。`sha256` 只作用于**规范化 JSON 文本**
（`description` 不进哈希、`semantic` 进）—— 它是 `policy_hash` 的来源，也是「三方比对」的基础。

**② 证书信封（第 5 环产物）** —— 标准 **DSSE** 信封，载荷字段（下为一次真实运行的原样结构，已截断长哈希）：

```jsonc
{
  "cert_version": "v1",
  "mode": "tool-call",              // public / private / stream / tool-call
  "policy": {"id": "agent-tool-v1", "version": "0.1.0"},
  "policy_hash": "68a1961f…",       // 策略指纹：换一个字符就不同
  "outcome": {                      // ★ 证明公开值的镜像 —— 电路里有的字段才在这里
    "passed": true, "violations": [], "trace_root": "9dc153f7…", "zk": true
  },
  "trace_seal": {"count": 1, "trace_root": "9dc153f7…", "ts": "…",
                 "keyid": "ed25519:40ad5f32…", "sig": "6d3355a2…"},  // ★ 顶层旁证，不进 outcome
  "binding": {"proof_mode": "unproven", "vkey_hash": "unproven",
              "proof_sha256": null, "public_values_sha256": null},
  "ai_act": {"art12_record_keeping": {"anchored": true, "per_call_record": true,
                                      "policy_hash_bound": true, "response_bound": false},
             "art13_transparency": {"mode": "tool-call", "outcome_disclosed": true,
                                    "policy_disclosed": true}},
  "ts": "2026-09-18T03:55:24Z"
}
```

两处设计要点，答辩时会被问到：

- **`outcome` 只放「电路公开值的镜像」**。证据、封装、EU AI Act 标注都在**顶层**，因为电路里没有这些字段 ——
  把链下东西塞进 `outcome` 会让「证明过的」与「没证明的」看起来一样。
  字段集合**随模式变化**：公开模式是 `{passed, violations, policy_hash, response_binding, trace_root, delegated}`，
  工具调用模式是 `{passed, violations, trace_root, zk}`（上例），私有模式换成承诺与脱敏见证。
- **`binding.proof_mode` 从一开始就写明这是不是证明**。宿主校验路径签出来的是 `unproven`，
  没有「看起来验过了」的空间；真要证明时它是 `core`/`compressed`（也可能是 `groth16`/`plonk`），
  并带 `vkey_hash` 与证明摘要。

### 4.3 判定引擎：八类规则，两种判定路径

**规则 8 类**（`policydsl/core/model.py` 顶部即权威清单）：

| 规则类 | 判什么 | 在哪判 |
|---|---|---|
| `keyword_block` | 字面命中禁用词 | **电路内** |
| `normalized_keyword_block` | 先按约束自带折叠表把同形异义字、零宽字符、全角折叠后再判 | **电路内** |
| `length_bound` | 长度上下界 | **电路内** |
| `pattern_block` | 正则子集（PII / 密钥 / 注入式样） | **电路内** |
| `format_check` | 格式合规（json/int/float，规范子集、确定性） | **电路内** |
| `tool_arg_guard` | 工具参数禁字段（判的是**回执**） | **电路内** |
| `budget_bound` | 累计预算 / 调用次数 | **电路内** |
| `semantic_bound` | 语义（主题级，学习型） | **委托 ezkl 陪伴证明** |

- **正则不是「拿来就用」**：只收一个**语法子集**，编译期 fail-fast 拒绝子集外的写法；
  再用 Thompson 构造编成**一个** NFA，由 **Pike VM** 判定（单趟、状态并集推进），Python 与 zkVM 两侧是同一台机器。
  逐起点重跑的朴素做法是 O(n²)、**可被对抗输入拖垮**（消融见 §7.3）。
- **两层各自实现，靠对拍对齐**：Python（`core/evaluate.py`）与 Rust（`circuits/`）**各写一遍**，CI 的 `rust` job 逐点比。
  基线落在 `tests/acceptance_baseline.json`（七面）与 `loader_parity_baseline.json`，比对结果 **exit 0/2/3 分档**。

### 4.4 轨迹绑定：回执链 + 会话末端承诺

工具轨迹**不再由 agent 自报** `tool_calls`，而是由**工具网关**在调用执行后签发**回执链**：

- 每条回执 `ToolReceipt{seq, tool, args, result_digest, ts, prev, keyid, sig}`，
  `prev` 把前一条的回执摘要串进来 —— 于是「链」这个结构本身就是承诺；
- 链的**结构**由电路保证：删一条 / 换一条 / 重排序 → `trace_unbound` **fail-closed**；
- **签发者身份**由链下 Ed25519 验签 + 公开值 `trace_root` 承担（电路内**不**验签名，见 §2.5）；
- **截尾**（整条删掉链尾那条违规回执）由网关的**会话末端承诺** `trace_seal{count, trace_root, ts, keyid, sig}` 拦 ——
  放在载荷**顶层**，因为它不在电路的公开值里；
- 验证方**必须给 `--gateway-key`** 才核得了签名，否则脚本如实标注「签名未验」。

> **一处刻意的「不给缺省值」**：`on_generate` / `on_tool_call` 的 `seal` 参数**不兜底**。
> 不传它的证书会在 `verify_cert.py` 的 `trace_seal` 卡上被判 **FAIL**（验证方给了网关公钥时）——
> 因为没有它就无法排除「链尾那条违规回执被整条删掉」，所以宁可不给默认值。

### 4.5 双隐私模式

同一条响应、同一条策略、同一个 nonce，两种模式各出一张证书，**判定结果必须相同**（脚本自己断言）：

| 验证方能看到 | 公开模式 | 私有模式 |
|---|---|---|
| 结论 / 策略指纹 | 相同 | 相同 |
| 命中了哪几条规则 | 相同 | 相同 |
| 每条规则的证据 | **明文**（如命中词 `exploit`、连密钥正则一起照抄） | **证据承诺**（哈希） |
| 响应本身的承诺 | —（该模式不承诺 `T`） | 有 |
| 脱敏见证 | — | `mask_count` / `mask_covered` |

私有模式的出口不是「涂黑」，而是**证据选择性开示**：开示一件证据时，该件必须与证书里那条承诺
**逐条相符**，篡改一件即被拒。**上界见 §9 第 1 条。**

### 4.6 三个 guest 与键分离

| guest | 证什么 | 为什么必须独立 |
|---|---|---|
| `pop-program` | 策略合规（域 `policy`） | 基准 |
| `pop-infer` | 推理完整性（**代理 MLP**，域 `infer`） | 与策略半**必须不同程序**（键分离），否则「这份证明属于哪一半」无从判断 |
| `pop-session` | 一组证书的跨证书一致性（`policy_hash` 全同 / 链无缝 / 覆盖完整轨迹，域 `session`） | 与前两域 vkey 不同 |

`Compose = (推理完整性 ∧ 策略合规)` 合成一张组合证书，回答「**这条 `T` 是被那个模型算出来的吗**」——
这个问题策略合规本身不覆盖。

### 4.7 服务化

两个阶段的时间尺度差 **4 个数量级**（宿主判定毫秒级 vs SP1 core 证明 ~2.5 分钟），所以拆两条接口：

- `POST /v1/check`：在线，毫秒级，证书如实标 `unproven`；
- `POST /v1/attest` → 轮询 `GET /v1/attest/{job}`：离线，真证明；两段传同一 nonce 时绑的是同一条 `T`。
- **并发上限是硬事实**：~10.15 GiB 是证明的固定地板，12 GB 机器同时只能跑一个 → 默认 `concurrency=1`，
  超出**排队**（队列满返 429，而不是收下之后 OOM）；**不可出证的策略当场拒**（返 400，`serviceable: false`）。

## 5. 可修改与可切换的模式 / 状态

### 5.1 运行时可以切什么

| 可切的东西 | 取值 | 怎么切 | 切了会怎样 |
|---|---|---|---|
| **隐私模式** | `public` / `private` | `AgentMonitor(policy, mode=…)` · `--mode` | 违规证据：明文 ↔ 证据承诺；私有另加响应绑定。**判定结果不变** |
| **证明模式** | `unproven` / `core` / `compressed` / `groth16` / `plonk` | `--prove` · `--proof-mode` | 写进 `binding.vkey_hash` + `proof_mode`；后两者本机**出不了**（T1） |
| **模型** | 离线桩 / 真 provider | `--model openai:<m>` / 不传 | 不传就打印 `llm model: fake (offline)` —— 如实标注，含糊不得 |
| **早停** | 软停 / 硬停 | `stop_on_violation` · `hard_stop` | 硬停真的**掐断传输**（抛 `EarlyStop`），被掐断那次没有 `on_llm_end` ⇒ 只有停止证书 |
| **判定口径** | 整链 / 单条 | `chain=gateway.receipts` / 新建网关 | 决定工具证书 `passed` 的含义：会话至今合规 ↔ 本次调用干净 |
| **语义规则** | 开 / 关 | 策略包里有没有 `semantic_bound` | 开则走 ezkl 陪伴证明；**流式路径会抛** `NotImplementedError`（未做，§9 第 10 条） |
| **账本 / 链上** | 只落账本 / 同时上链 | `--rpc` · `--contract` · `--private-key` | 不上链也能验证，只是少了「第三方时间戳」这一层 |
| **服务并发** | `--concurrency` / `--max-queue` | 启动参数（缺省 1 / 8） | 不是策略是**硬事实**：见 §4.7；队列满返 **429** |
| **服务鉴权** | 无 / token / `--require-auth` | `--auth-token` · `--auth-file` · `--auth-admin` | 没配也照常起，但 `/v1/health` 如实写 `auth: none`。权限**只有二元开关**（未做细粒度） |
| **服务预检** | 只宿主校验 / 真出证 | `--host-check` | 几秒完成并如实标 `proof_mode=unproven`，用来验队列机制本身 |
| **结果留痕** | 追加写 | `regression_prove.py --label …` | `regression-prove.jsonl` **只追加不覆盖**，任何一腿 FAIL 即非零退出 |

### 5.2 切换点长什么样（代码细节）

```python
# ① 隐私模式：一次会话选一次。判定结果必须相同，不同的只是「你看见什么」
monitor = AgentMonitor(policy, mode="private")          # public | private

# ② 生成路径：挑战值 + 整条回执链 + 会话末端承诺，三者一起进证书
cert = monitor.on_generate(resp, nonce=nonce, receipts=gw.receipts,
                           seal=gw.seal(), vkey_hash=vk, proof_mode="core")

# ③ 工具路径：判的是网关**执行后**签发的真回执，不是 agent 自报的 {name, args}
cert = monitor.on_tool_call(receipt, chain=gw.receipts, seal=gw.seal())

# ④ 判定做不了时（fail-closed）：仍然出证，但 passed=False + 顶层 judgment 块
#    {"performed": false, "type": …, "message_sha256": …}   —— 不留孤儿回执
```

```bash
# 演示：换模型 / 换模式 / 加挑战绑定 / 公私对比
python3 scripts/demo/demo_e2e.py --model openai:<model> --prove \
        --proof-mode core --nonce <hex> --contrast-prove

# 证明服务：并发、队列、鉴权、锚定
python3 scripts/ops/proof_service.py --concurrency 1 --max-queue 8 \
        --mode private --proof-mode core --require-auth --rpc $RPC --contract $ADDR
```

**三处刻意的「不给缺省值」**：`seal`（不给就无法排除截尾，宁可让验证 FAIL）、
`proof_mode`（未标注一律 `unknown`，**不**做「未知即安全」的默认 —— 那正是隐藏程度表要防的错误）、
`concurrency`（缺省 1 是硬约束而非保守取值：同时跑两个证明器是 OOM，不是慢）。

### 5.3 有哪些是可以修改的、代价多大

| 想改什么 | 改哪儿 | 代价 |
|---|---|---|
| **调策略**（换禁用词、改长度、加正则） | 直接改 `policy_packs/*.json`，重编译即换 `policy_hash` | **极小**：不改代码 |
| **接一个新框架** | 实现两个回调 + 一会话一把 `ToolGateway`（照 `GenericGuard` 抄） | **小**：加一个适配器文件 |
| **换签名算法** | 实现 `cert.Signer` 协议（`sign` / `keyid` / `public_key`） | **小**：证书其余部分不动 |
| **换锚定后端** | `evidence/ledger.py` 的写入端 / 换一个同类 `Anchor.sol` | **小** |
| **加一类规则** | `core/model.py` 加 kind + `evaluate.py` 实现 + **电路侧 `pop-program`** + 更新两条对拍基线 | **中**：必须同时动 Python 与 Rust |
| **换语义模型** | `semantic/` 的模型与 `training_report.json`；`encode` 须保持**单射** | **中**：需真实数据集与更大模型 |
| **换证明系统** | 电路在 `circuits/`（三个 guest 入口）；`proof_mode` 已预留 `groth16`/`plonk` | **大**：需 ≥64 GB 机器（T1） |

> **一条自我约束**：「加一类规则」是**唯一**必须跨层改的扩展点。它不是缺陷，而是「电路内判定」这个选择
> 本身的代价。项目用**对拍基线 + fail-fast 语法闸门**把这份代价压到「改了必须留证据」，而不是「改了看不出来」。

## 7. 创新点与思路

### 7.1 空位在哪

已有的四派各自不足：TEE 证明「护栏执行过」而**执行 ≠ 合规**；治理栈同样依赖 TEE 与厂商设施；
形式验证需要人工形式化且**对黑盒响应不适用**；ZK 正则/PII 只是**积木**而非系统。
「**通用策略 DSL → ZK 约束编译 + 无硬件信任 + 双隐私模式 + 形式化安全模型 + 开源**」的组合此前无人系统化。

### 7.2 四项贡献

1. **PoP 系统**：通用 DSL → ZK 判定 → 双隐私模式 → 合规证书的开源端到端实现（8 条支路）。
2. **可序列化 NFA 契约**：正则子集跨层（Python ↔ zkVM）一致，含 fail-fast 语法子集与 Pike VM 判定。
3. **形式化安全模型**：游戏 + 归约，含健全性 / 承诺式隐私 / 不可伪造 / 绑定 / 记录完整性，
   外加三条「推广到单条响应之外」的引理（L6 组合 / L8 跨证书 / L9 多证明者），**每条给出代码落点**。
4. **评测**：周期数矩阵、NFA 消融（含对抗输入下的二次退化）、真实证明时间/大小/内存、信任-成本四象限。

### 7.3 消融（最容易讲清「设计对不对」的一组数字）

病理输入（`a`×n 对正则 `a+b`）下朴素实现 vs Pike VM：

| n | Pike | 朴素 | 比值 |
|---:|---:|---:|---:|
| 100 | 643,894 | 12,382,720 | **19.2×** |
| 200 | 1,145,209 | 48,638,946 | **42.5×** |
| 400 | 2,143,617 | 193,207,130 | **90.1×** |

比值随 n **翻倍** ⇒ 朴素做法是 O(n²)、可被**对抗输入**拖垮，Pike 保持线性。这就是「默认必须用 Pike」的证据。

自然语言上两者只差 1.5–2.1× —— 所以**如果只测常规文本，会得出「随便哪种都行」的错误结论**。

### 7.4 与最贴近的同期工作（zkAgent, ePrint 2026/199）对标

| 维度 | 本项目 | zkAgent |
|---|---|---|
| 证明时间 | 118.9–172.5 s | 194.40 s / ~1069 s |
| 验证时间 | ~0.090 s | 0.42 s / 0.038 s |
| 证明大小 | ~2.7 MiB | ~96 MiB / 3.1 MiB |
| 硬件 | **24 核 / 12 GB** | 32 核 / **512 GB** |
| 内容隐私 | 承诺式（双模式 + 选择性开示） | 无 |

**口径很重要**：本项目**不主张「更快」**，主张的是「对『合规』这条义务，在不涉及模型的前提下以**同量级时间、
更小内存**完成，并补上承诺式隐私」。

## 8. 实用价值

### 8.1 定位

**离线审计 / 报送 / 批量合规核查**，不是实时护栏。取舍一句话：每次开销从「硬件延迟」变成「证明时间」，
换来**无硬件信任 + 内容隐私**。

### 8.2 EU AI Act 工程映射（**证书里就带着**）

映射不止写在文档里 —— 每张证书载荷里有一个 `ai_act` 块（见 §4.2），把义务**逐条落到具体字段**：

| 义务 | 落点 |
|---|---|
| Art.12 记录保存 | 每张证书 `cert_version`/`ts`；`policy_hash` + `binding{vkey_hash, proof_sha256, proof_mode}` 绑定策略版本与电路；`cert_digest` 入防篡改锚定账本；粒度为**单次响应 / 单次工具调用** |
| Art.13 透明性 | `mode` / `outcome` 告知内容是否公开、是否合规；验证方可独立复算；私有模式只公开承诺 |

> 文档明确标注这是**工程映射、非法律意见**；`training data / 模型卡`（Art.11）明确记为**超出范围**。

### 8.3 部署形态

- **审计路径免证明器**：`circuits/verifier`（`pop-verify`）让验证方**不需要构建 prover** 即可验证。
- **常驻服务**：`scripts/ops/proof_service.py`，两段接口 + 排队 + 满载 429（见 §4.7）。
- **链上锚定**：`contracts/Anchor.sol` + 本地 Anvil 一键端到端。合约只存
  `mapping(bytes32 digest => uint256 ts)`，`anchor()` 是 **first-write-wins**（重复锚定回滚），
  另有 `anchoredAt`/`anchoredBy`/`isAnchored` 与 `Anchored(digest, ts, by, seq)` 事件；ABI + bytecode 已入库，
  **部署不需要 solc**。
- **语义规则的成本**（ezkl 陪伴证明，离线批处理）：setup 48.2 s / 出证 **76.6 s（峰值 8.72 GiB，证明 40 KiB）** /
  验证 1.0 s —— 约 77 s/条响应，这也是它被定位成**离线审计**而不是实时护栏的直接原因。
- **接入现实框架**：LangChain / LangGraph / MCP 三个适配器已实测；接自己的框架只需实现
  `AgentMonitor.on_generate` / `on_tool_call` + 一会话一把 `ToolGateway`。

## 9. 还未解决的问题（如实清单）

按「影响 × 是否有出路」排。**先说结论**：真正挡住收尾的只有一条 —— **第 2 条的内存天花板**，
它的具体后果就是 §6.1 的 T1（租 ≥64 GB 云机出 groth16 证明 + 测通链上验证合约）。其余九条都是
「已登记、有归口、不挡主路」的边界。

| # | 问题 | 现状与影响 | 出路 |
|---|---|---|---|
| 1 | **私有模式的隐私上界** | 只保证「公开值不含明文」。**两个独立理由**：① SP1 `core`/`compressed` 非零知识（官方安全模型明文 + 本机源码审计）；② 更根本地，「响应绑定」与「内容隐藏」对**低熵 `T` 互斥** —— 公开值里的响应承诺可离线枚举猜测-验证，这与证明系统无关 | 要「不可恢复」需换零知识证明系统（如 groth16/plonk 隐藏见证），**本机内存不够、仅设计上可行未实测** |

## 11. 附录：导师可能追问的 8 个问题

| 问题 | 一句话备答 |
|---|---|
| 「你这个和 ZKML / zkAgent 有什么区别？」 | 它们证**模型算得对**，我们证**输出满足策略** —— 义务不同。zkAgent 覆盖推理完整性，代价是依赖模型；我们**不涉模型**，因此能在 24 核/12 GB 上以同量级时间出证。两者是互补的，我们的组合证明就是想把两者合起来（当前推理半是代理）。 |
| 「不用 TEE，那凭什么信？」 | 信的是**zkVM 的健全性 + 哈希**，不是硬件。网关仍需信任（假设 A4），这是模型里**最弱的一环**，已如实标注。 |
| 「零知识？那我把你的响应反推出来？」 | 反推不出**明文**，但**能对低熵文本做猜测-验证**。这条是我们自己查出来并写进标题与 README 的，不是被问出来的。要更强的保证得换证明系统。 |
| 「一次证明多少钱 / 多久？」 | 本机（24 核 / 11.7 GiB）：**118.9–172.5 s、2.7 MiB、峰值 ~10.4 GiB**；瓶颈是**内存不是 CPU**，固定地板 ~10.15 GiB。 |
| 「策略复杂了会不会爆？」 | 会，且有明确边界：成本由 **NFA 扫描 × 文本长度**主导，不由规则条数主导（一条 NFA 正则边际 ≈3,634 周期/字符，一条关键词 ≈31.6，差 **115 倍**）。可行域是「两级台阶」，3 条规则 × 200 字符在本机就 OOM。 |
| 「怎么保证你的判定和电路判定一致？」 | 两层各自实现 + **跨语言对拍**（CI 的 `rust` job 逐点比），且编译期有 fail-fast 语法子集闸门。 |
| 「工具调用是 agent 自报的吗？」 | 不是 —— 网关在调用**执行后**签发回执链，结构由电路保证（删/改/重排 → fail-closed），**截尾**由会话末端承诺拦。验签在链下，这条如实标注。 |
| 「论文投哪、现在什么状态？」 | `paper/proof-of-policy.tex` 结构完整（摘要 → 相关工作 → 威胁模型 → 系统 → 安全模型 L1–L9 → 实现 → 评测 7 节 → 局限 → 结论 → 复现附录），标注为**工作稿 Phase 6 / W8**；作者信息未填，投稿目标待定（CCS/USENIX/S&P/NDSS，退 PoPETs）。 |
