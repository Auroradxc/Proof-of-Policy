问题

「我的 agent 是合规的」——这句话凭什么信？

① 日志可伪造
运营方自己记的日志，自己就能改。审计方拿到的是一份声明，不是证据。
② 「护栏跑过了」≠「合规了」
TEE 路线证明的是护栏代码被执行过（执行 ≠ 合规），而且要把输入输出交给第三方硬件。
③ 隐私与可核验相互顶牛
要把响应交出来才能验 —— 可一旦交出来，合规的那部分内容也一并泄露了。
本项目要的东西：一份验证方自己算得出来的证据
给定公开策略 π 与一条响应 T，任何人都能独立验证「T 满足 π」； 而违规内容只以证据承诺披露 —— 结论公开、内容不公开、无硬件信任。
坐标系（docs/quadrant.md）
纵轴＝证明性质成立还是护栏执行过；横轴＝信任来自密码学还是硬件/人工。 「密码学健全 × 证性质」这一格此前为空，本项目落在该格。
一句话边界
证的是策略满足性，不是推理正确性；不涉及模型权重，也不证明「这条 T 一定是那个 LLM 算出来的」。

设计细节 · 层间合同

两层之间只签两份合同

① ConstraintSpec：策略 → 约束
spec_version / policy_id / policy_version / semantic / constraints[] / sha256。
sha256 只作用于规范化 JSON 文本（description 不进哈希）—— 它就是 policy_hash 的来源，也是三方比对的基础：出证方、验证方、电路公开值， 三方现场重编译必须得到同一个值。
跨语言对拍：Python 参考层与 Rust/SP1 电路层各自实现判定，CI 的 rust job 逐点比。
② 证书：outcome 与顶层不是一层
outcome 只放电路公开值的镜像：公开模式为 {passed, violations, policy_hash, response_binding, trace_root, delegated}。
trace_seal（会话末端承诺）、ai_act（合规标注）、binding、 error 块一律在顶层 —— 因为电路里没有这些字段。
把链下东西塞进 outcome，会让「证明过的」与「没证明的」看起来一样。
三个哈希，各绑一件事（都在域分隔符下）
名字定义绑什么
response_bindingSHA256("pop-bind-v1" ‖ u32be(len(nonce)) ‖ nonce ‖ T)绑到这一条响应，防调包
trace_root回执链末条回执的摘要（链起于 TRACE_GENESIS）绑整条工具轨迹
policy_hash策略包规范化 JSON 的 sha256绑策略版本
域分隔符是「同一哈希在两个用途下互不冒充」的全部实现。写错一个字符的后果不是报错， 而是两侧各自自洽、合起来对不上 —— 所以有一条测试逐字节比对四个域 （pop-trace-v1 / pop-bind-v1 / pop-infer-v1 / pop-session-node-v1） 在 Python 与 Rust 两侧的字面量，且它不需要 Rust 工具链，因此进得了零依赖的 CI 通道。
设计细节 · 轨迹绑定

工具调用不是 agent 自报的

由工具网关在调用执行后签发回执链
每条 ToolReceipt{seq, tool, args, result_digest, ts, prev, keyid, sig}， prev 把前一条的摘要串进来 —— 「链」这个结构本身就是承诺。
结构
由电路保证：删一条 / 换一条 / 重排序 → trace_unbound fail-closed
身份
链下 Ed25519 验签 + 公开值 trace_root（电路内不验签名，如实标注）
截尾
网关的会话末端承诺 ToolSeal{count, trace_root, ts, keyid, sig} 拦
前提
验证方须给 --gateway-key，否则脚本如实标注「签名未验」
为什么要专门拦「截尾」
把链尾那条违规回执整条删掉，剩下的前缀依然是一条合法的链 —— 这类攻击不破坏任何哈希， 只有「承诺的条数/根 vs 实际交付的条数/根」的比对才拦得住。
如实标注的边界

会话聚合电路不验网关签名（zkVM 里没有网关公钥）；且 [0..k] 前缀的 index/prev 依然连续 —— 即电路本身接受一个被砍了尾巴的证书集， 拦下它的是链下的根比对。

设计细节 · 双隐私模式

同一条响应、同一条策略、同一个 nonce —— 差别只在「你看见什么」

验证方能看到公开模式私有模式
结论 passed相同相同
策略指纹 policy_hash相同相同
命中了哪几条规则相同相同
每条规则的证据明文：命中词 exploit、连密钥正则 sk-[A-Za-z0-9]{16,} 一起照抄证据承诺（哈希）+ 脱敏见证
响应本身的承诺—（该模式不承诺 T）有
判定结果必须相同
同一个 T、同一条策略，所以两张证书的 policy_hash 与 passed 一致 —— 脚本自己断言这一点，不一致就是 FAIL。差别只在验证方看得见什么。
私有模式的出口不是「涂黑」
是证据选择性开示：开示一件证据时，该件必须与证书里那条承诺 逐条相符，篡改一件即被拒。
这条的自我限制（本项目的核心诚实项）

私有模式保证的是「公开值不含明文」，不是「响应内容不可恢复」—— 公开值里的响应承诺是 T 的公开函数，对低熵文本可离线枚举猜测-验证。

设计细节 · ZK 电路

三个 guest 程序，键必须分离

guest证什么域公开输入
pop-program策略合规（8 类规则，语义规则登记委托）"policy"Outcome
pop-infer推理完整性（代理 MLP，权重为编译期常量）"infer"InferOutput
pop-session跨证书一致性：policy_hash 全同 / 链无缝 / 覆盖完整轨迹"session"SessionOutput
为什么必须不同程序（键分离）
两个 guest 入口各断言一次自己的域。否则「这份证明属于哪一半」无从判断 —— 同一把 vkey 既能签策略结论又能签推理结论，组合证明就成了各说各话。
组合证明回答的问题
Compose = (推理完整性 ∧ 策略合规) —— 回答 「这条 T 是被那个模型算出来的吗」，这是策略合规本身不覆盖的问题。
如实标注

推理半当前是代理（确定性定点 MLP），不是真实 LLM 的推理证明； 且「组合成本由推理主导」在代理规模下不成立（如实写进了评测）。

问题现状与影响出路
① 私有模式的隐私上界 只保证「公开值不含明文」。两个独立理由：SP1 core/compressed 证明非零知识（官方安全模型明文 + 本机源码审计）；更根本地，「响应绑定」与「内容隐藏」对低熵 T 互斥 —— 公开值里的承诺可离线枚举猜测-验证，与证明系统无关 要「不可恢复」须换零知识证明系统（groth16/plonk 隐藏见证）：本机内存不够，仅设计上可行、未实测
② 内存天花板 prover 固定地板 ~10.15 GiB：最小配置（200 字符 × 1 规则）就已 10.39 GiB。本机 11.7 GiB 下，3 规则 × 200 字符、1 规则 × 20k 字符均被 OOM 杀；可行域呈「两级台阶」 换 ≥16 GB 机器；已把「OOM 判据」写成测试（复刻被杀时的无输出无末行）
③ 组合证明的推理半是代理 pop-infer 是确定性定点 MLP，不是真实 LLM 的推理证明；「组合成本由推理主导」在代理规模下不成立（如实写进评测） 需要真实模型的推理证明（zkAgent 方向），其源码不可得 —— 属另一条工作线
④ 语义规则的三条硬边界 passed=true 且 delegated 非空的证明不等于策略被满足（验证脚本因此打印两行：RESULT: 与 合规:）；只支持公开模式（encode 在词表上单射，可反查原文）；随包模型是演示用小模型（留出集 acc 0.99 / n=100），不构成语义安全保证 换更强的私有语义证明路线；模型侧需要真实数据集与更大模型
