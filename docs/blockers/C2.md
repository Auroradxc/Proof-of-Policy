# C2 blocker：电路级披露 MVP 的边界与未做项

> **状态**：2026-11-01，分支 `bhv/c2-circuit-disclosure`，基线 `1c1fc60`。
> 实现记录见 [`../experiments/circuit-disclosure.md`](../experiments/circuit-disclosure.md)；
> 设计见 [`../design-disclosure-levels.md`](../design-disclosure-levels.md)。
> 本文件只记录**降级、阻塞与迁移债**，不重复测试矩阵。

## 一句话

L0/L1/L2 现在是**电路级**公开值形状（`pop-pv-v2`），验证方不再重投影。
但本轮是 **MVP**：`delegated` 的类别桶没实现（L1/L2 fail closed）、只跑 core、
旧 v1 证明默认拒绝且新 binary 不能解码旧公开值、宿主镜像与部分脚本/bench
仍停在 v1。

## 已落地（本轮）

- `ProofRequest` / `PrivateRequest` 的 `disclosure_level`（serde 默认 L0）；
- guest 在 commit 前生成 L0/L1/L2 形状；`public_value_schema = "pop-pv-v2"`
  与 `disclosure_level` 进公开值；
- L0 不再输出明文 `evidence`（只留带盐承诺）；
- L1 类别桶 + 桶承诺 + `violation_count`；L2 逐条承诺排序；
- Python v2 承诺助手与 Rust 逐字节对拍（固定 fixture 两侧同读）；
- `verify_cert.py` 只做 schema/级别/形状/逐字段相等；`--legacy-v1` 仅 L0；
- Python 类别映射补上 `retrieval_guard`。

## 阻塞 / 降级（不要 overclaim）

1. **delegated 类别桶未实现**（A9 §6）。
   - `DelegatedBucket` 类型与 `rule_name` / `names` 承诺已写好；
   - 电路内分组、桶排序、`names_commitment`、陪伴证明按桶匹配**未做**；
   - 后果：含 `semantic_bound` 的策略在 L1/L2 下**产不出证明**（guest panic，
     fail closed）。要出证只能用 L0（名字可见）。
2. **只跑 core，未跑 groth16/plonk**。
   - `core` / `compressed` 工件仍泄露 raw 见证（规则名/类型/证据），与设计
     §10.2 一致；本轮不主张「策略对拿到工件的人隐藏」。
   - 云机（AutoDL `connect.bjb2.seetacloud.com:37499`，16 核 / 90 GiB）
     已连上并在 `/root/autodl-tmp/zk-policy-c2` 独立目录完成 C2 build；
     L0/L1/L2 core 证明与 `--verify` 均在云机跑（见实验文档 §6）。
   - **vkey 跨构建机不可复现**：云机 rustc 1.99.1 编出的 ELF/vkey 与本机
     1.98.1 不同（云机 policy vkey `0x000cfdfc…`，本机 `0x00fa5119…`）。
     实验结果只引用云机 vkey；本机证明只作 smoke test。groth16/plonk 仍未跑
     （需要 `SP1_GROTH16_CIRCUIT_PATH` 与更长时间，本轮未纳入 C2 验收）。
3. **旧 v1 证明默认拒绝，且缺少归档验证器**。
   - `--legacy-v1` 只在证书/外部 `proof_result` 已是 v1 JSON 时有用；
   - 新 `pop-script` 的 `Outcome` 类型已改为 `DisclosedViolation`，**无法解码
     旧 v1 证明文件**；要继续验证旧工件必须归档旧 binary（本轮未做）。
4. **宿主判定镜像未同步**（超出硬边界）。
   - `policydsl/runtime/service.py::host_outcome` 仍输出 v1 raw shape；
   - 受此影响：`tests/test_proof_service.py` 的形状断言、以及任何
     `/v1/check` / `/v1/attest` 无证明路径，都会与新电路公开值不同形；
   - 这是**已知迁移债**，不是静默通过：验证 v2 证书时若载荷带 schema，
     `verify_cert.py` 会按 v2 检查；宿主镜像需单独改。
5. **`verify_session.py` 仍按旧披露路径**（硬边界只允许改 `verify_cert.py`）。
   - 会话聚合里若混入 v2 证书，`projected_proof_outcome` 的重投影路径需要
     后续同步；本轮未改，也未在会话测试中宣称 v2 已覆盖。
6. **`bench/bench_policy_corpus.py` 仍用证书层投影**。
   - 它用 v1 raw outcome + `cert.build_payload(disclosure_level=...)`；新
     `build_payload` 对 v1 outcome 要求级别会 fail closed。推断实验需在
     切换到真实 v2 公开值后重跑（本轮未跑）。
7. **vkey 全量重建**：`pop-types` 被三个 guest 共享，即使推理/会话语义没改，
   ELF/vkey 也可能变。记录见实验文档 §5；旧 vkey 结果保持历史，不混表。

## 实现中踩到的坑：bincode 与 tagged enum

SP1 公开值用 **bincode** 编解码。第一版把 `DisclosedViolation` 写成
internally-tagged enum（`#[serde(tag = "shape")]`），core 证明**跑完到最后读公开
值时** panic：

```text
failed to deserialize: DeserializeAnyNotSupported
```

原因：tagged/untagged enum 依赖 `deserialize_any`，bincode 不支持。修法是改成
固定字段 struct（`shape` + `Option`），JSON 的精确形状由 `to_json_value()`
手工摊平；同时 `violation_count` 等字段**不能**用 `skip_serializing_if`
（会让 bincode 流错位），L0/L2 的「键不出现」只在 JSON 侧做。这个坑值得写进
后续「改公开值类型」的检查单：**任何派生 Serde 的公开值类型都要用 bincode
round-trip 验证，而不是只看 serde_json。**

## 失败面（本轮刻意选择的 fail closed）

- 未知 schema / 级别；证书级别 ≠ 公开值级别；
- L0 带 `violation_count`；L1 桶乱序/重复/计数不符；L2 承诺乱序；
- 任何级别出现多余键或禁用键（L1/L2 的 `rule`/`kind`/`name`/`evidence`）；
- L1/L2 非空 `delegated`；任何非空 `delegated_buckets`；
- 私有模式带非空 `delegated`；
- 证书载荷 ≠ 解码公开值；v1 证明冒充 v2；v2 证书配 v1 证明。
