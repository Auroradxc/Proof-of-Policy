# C1 blocker：证书层的披露不是电路级隐藏

> **状态**：P1-05 / P1-06 / P1-07 / P1-08 落地记录（2026-11-01，分支 `bhv/c1-cert`）。
> 本文件只记录**边界、已知缺口与下一步**；实验数字在
> `bench/results/policy_infer.md` 与 `bench/results/delivery_binding.md`。

## 一句话

**L0/L1/L2 是证书层的披露投影，不是电路级隐藏。** SP1 guest 仍然把每条违规的
raw `rule` / `kind` 写进证明公开值；`policydsl/evidence/disclosure.py` 只在
证书载荷里把它们投影成该级别允许的形状，验证方用同一函数重投影证明公开值后
比对。第三方若直接读取证明公开值（或 `core` 档的证明工件），仍然能看到
raw `rule` / `kind`。

**电路级 coarsening（让公开值本身只含类别）需要单独改电路并重建 vkey，
不属于 C1 的范围，也没有在本次改动中发生。**

## 仍然存在的缺口（不要 overclaim）

1. **证明公开值通道**：电路仍输出 raw `rule` / `kind`。L1/L2 只影响证书载荷；
   拿到证明公开值的人仍可恢复规则名/类型。
2. **证明工件通道**：`core` / `compressed` STARK 不隐藏见证；`π` 仍可能从
   trace 泄露。需要 `groth16` / `plonk` 的 witness-hiding（见
   `docs/certificate-binding-framework.md` §7.3 与 `docs/sp1-zk-audit.md`）。
3. **`delegated`**：委托约束的 `name` 就是规则名。L1/L2 目前对非空
   `delegated` **fail closed**；类别级的 delegated 披露协议尚未定义。
4. **重执行通道**：盐与披露层级都不保护「行为」；对手知道部署上下文时
   `k_π` 可能很低，P1-06 的推断准确率就是这条债的度量。
5. **end-user nonce 与电路**：电路仍用 verifier 域 `pop-bind-v1` 计算
   `response_binding`；end-user 绑定是证书 challenge 块里的**附加**字段
   `end_user_binding`（新域 `pop-bind-enduser-v1`），不改变电路公开值。

## 下一步

- 电路级 coarsening 需要独立的 vkey 重建任务（改 `circuits/types` 的公开
  输出形状并重出 vkey）；本分支**没有**做。
- 若要端到端使用 end-user nonce，需要把 U 的 nonce 也交给电路（或让电路
  接受 issuer 域参数），同样需要改电路与 vkey。
- `delegated` 的类别级披露需要先定义类别 schema，再决定它进电路还是只进
  证书层。
