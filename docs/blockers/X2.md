> `bhv/x2-llm`（基线 `c78ca67`）。**没有未解决的阻塞**；真实采样与端到端均已完成。
> 本文件记录环境绕行与**方法边界**，避免把结果读过头。

## 一句话

在 AutoDL 的 RTX 5090（32 GB）上用 `Qwen/Qwen2.5-7B-Instruct`（fp16）跑了
50 prompt × 20 采样 × 2 温度 = **2000 条真实样本**，产物见
[`k_entropy.md`](../../bench/results/k_entropy.md) 与
[`real_llm_e2e.md`](../../bench/results/real_llm_e2e.md)。采样主结论：
温度 0 时 `k=0`（确定性，重执行即恢复）；温度 0.7 时 `k=4.32 bit`，且该值
**恰好是 N=20 的估计上限**（见下文边界 3）。

## 已解决的环境阻塞（不阻塞交付）

1. **`huggingface_hub` 2.4.0 + `httpx2` 2.14.0 与旧 `brotlipy` 0.7.0 冲突**：
   `snapshot_download` 在 brotli 解码处抛
   `TypeError: Decompressor.decompress() got an unexpected keyword argument 'output_buffer_limit'`。
   处理：`pip uninstall brotlipy`，让 `httpx2` 改走 gzip/identity。
2. **`huggingface.co` 直连超时**：设 `HF_ENDPOINT=https://hf-mirror.com`。
3. **镜像不代理 Xet CAS**：`xethub.hf.co` 返回 401。设 `HF_HUB_DISABLE_XET=1`，
   改走普通 HTTP 下载（14 个文件全部成功，约 23 分钟）。
4. **系统盘只剩 17 GB**：设 `HF_HOME=/root/autodl-tmp/hf-cache`，模型落在
   150 GB 数据盘。

依赖版本：`torch 2.14.1+cu130`、`transformers 5.20.2`、`accelerate 1.15.0`；
GPU 为 RTX 5090（sm_120），cgroup 16 CPU / 90 GiB。

## 方法边界（论文必须写）

1. **XSTest 标签是 prompt 级**。响应级没有 ground truth，所以
   `response_policy` 只报运行指标（违规数/率），不伪造 P/R/F1。
2. **`refusal_proxy` 是前缀启发式**（`I can't` / `I'm sorry` / `As an AI` /
   `抱歉` …），不是人工标注。
3. **`k` 被采样数截断**：`p_max ≥ 1/N`，故 `k ≤ log2(N)`。温度 0.7 的 50 组
   全部 **20/20 响应互不相同**，于是 `k = log2(20) = 4.32 bit` 恰好是 N 的上限。
   它只说明「20 个样本里没有重复」，**不是**真实熵，也不是信息论上界；真实熵
   可能更高，本数据无法区分。
4. **本地 backend 未套 Qwen chat template**：`bench_k_entropy.py` 直接把原始
   prompt 喂给 Instruct 模型，行为更接近**续写**而非对话作答。因此端到端的
   96% 响应违规率/10% 拒绝率是「关键词策略 + 续写文本」的运行指标，**不能**
   解读为聊天模型的实际拒答率。要得到对话口径，需要在 backend 里套 chat
   template —— 本任务未改脚本。
5. **温度 0 的 `k=0` 是确定性的直接后果**：`p_max=1`，重执行一次模型即可恢复
   `T`（`Corollary reexec`），这与证明系统是否正确无关。
