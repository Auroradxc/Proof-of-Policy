# B1 blockers（P1-10 / P1-12 / P1-13）

本文件只登记**做不了 / 不能按原计划做**的项，以及解除条件。能做但没做的，
不写在这里（写进对应 `bench/results/*.md` 的「诚实边界」）。

## B1-circuit-ed25519：SP1 电路内 Ed25519 验签（P1-10b）

**状态**：`blocked`。`bench/results/gateway_sig.json` 的 `circuit` 字段记
`status="blocked"`，`cycles` / `prove_time_s` / `peak_mem_mb` 全为 `null`。
**不伪造任何周期数、证明时间或内存数字。**

### 为什么做不了（三条同时成立）

1. **电路里没有这段代码，而且按设计就是这样。**
   `circuits/types/src/lib.rs` 的 `ToolReceipt` 注释明确写着 `sig` 字段
   **刻意不在**电路视图里：「Ed25519 验签在**链下**由网关公钥完成（zkVM 内验签
   代价高）」。`docs/security-model.md` §5.3 也把「网关签名」列为链下 + 证书层。
   电路内验证的是回执链的**结构**（`verify_receipt_chain`），不是签名。
2. **要量它必须新增 guest crate / 改电路。**
   B1 的文件所有权只覆盖
   `bench/bench_gateway_sig.py`、`bench/bench_baselines.py`、
   `policydsl/evidence/transparency.py`、`tests/test_transparency.py`、
   `bench/bench_issuance.py`、对应 `bench/results/*` 与本文件。
   `circuits/` 明确列为**不改**；新增一个测 Ed25519 的 guest 仍然越界。
3. **本机没有证明锁，且内存不够并发。**
   本机 14.6 GiB；SP1 `core` 证明的固定内存地板约 10.15 GiB
   （`bench/comparison_zkagent.md` §2、`bench/results/proofs.md`）。约定要求
   拿到 `flock /tmp/pop-proof.lock` 才能跑小规模证明；本次开工时该锁不存在。
   即使只跑执行（不出证），也需要先建 guest 工件，仍受第 2 条约束。

### 解除条件（满足任意一条才能给数字）

- 由 **C1/电路 owner** 在 `circuits/` 增加一个「验一条 Ed25519 回执」的
  guest（或给现有 program 加一个开关），B1 只调用它并量测；或
- 明确授权 B1 在 `circuits/` 之外新建独立 guest crate，并分配
  `CARGO_TARGET_DIR`，避免与其它 agent 抢 target 锁；且
- 持有 `flock /tmp/pop-proof.lock`（或确认无并发证明任务），再跑小规模。

### 现在能说的 / 不能说的

- **能说**：链下 Ed25519 验签的成本已实测（见 `gateway_sig.md` 表 a）；
  2-of-3 多签原型的签名/验签/证书大小已实测（表 c）。
- **不能说**：电路内验签「只贵一点」或「大约多少周期」——本实验没有这个数。
  任何把链下成本当作电路内成本的推断都是无依据的。
- **能说**：现有设计把验签放在链下，因此信任根里仍有「网关」这一项
  （`docs/security-model.md` §5.4 的 A4）。

## B1-baseline-numbers：Zaguk / PCO 的可比性能数字（P1-12）

**状态**：部分 `cited`，性能格留 `—`。

- **Zaguk**（JNIC'26）原文是会议论文集 PDF
  (`https://www.incibe.es/sites/default/files/eventos/JNIC/JNIC26-Acta-red.pdf`)。
  本环境访问该主机被拒（`ECONNREFUSED`），只能从检索摘要取得**定性**结论
  （证明生成是主成本；证明大小/验证时间随编码长度稳定），**没有**可核对的
  具体毫秒/字节数。因此 `baselines.md` 的 Zaguk 性能格写 `—`，并标 `cited`。
- **PCO**（IACR ePrint 2026/994）摘要页可访问，但**未报告**性能数字；
  `baselines.md` 的 PCO 性能格写 `—`。
- **NiyamAI**（arXiv:2608.07167）摘要给出了 1.7 s/action、51 ms 验证、
  18.6 KB 证明，已引用。
- **zkAgent** 的数字来自本仓库 `bench/comparison_zkagent.md` 对 ePrint 2026/199
  的摘录，已引用。

**解除条件**：拿到 Zaguk 论文 PDF 的完整表格后补数字；PCO 若后续版本给出
性能数字再补。**在此之前不得给这两列编数**。

## B1-split-view：透明日志原型的防 split-view（P1-13）

**状态**：未实现（`policydsl/evidence/transparency.py` 的 `checkpoint()` 只是起点）。

定理 F2 需要日志「只追加 + 可公开读 + 树头签名 + 一致性证明/gossip」。
本原型实现了：只追加语义、包含证明、树头签名（可选）、检查点。
**没有**实现：一致性证明、gossip、跨审计者视图比较。因此
`bench/results/issuance.md` 的实验前提里把 F-2 写成外部假设，而不是已交付的性质。

**解除条件**：接入一个真实的透明日志（如 RFC 6962 风格的一致性证明 + 公开
gossip 通道），或由部署方提供「审计者之间会比较树头」的外部机制。

## B1-issuance-f5：检出 ≠ 阻止（P1-13）

**状态**：模型边界，不是实现缺陷。

`bench_issuance.py` 只算「被发现」的概率，不算罚则/经济激励下的「被阻止」。
这是证明债 F-5；论文必须写 `detection only`。本实验不尝试补它。
