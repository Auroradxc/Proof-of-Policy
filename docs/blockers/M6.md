## 3. 边界声明

- 本文件**不是**「镜像构建成功」的记录；它记录的是**为什么没有构建**、以及做了哪些
  等价检查。任何投稿材料都不得写「Docker 镜像已实测」。
- 没有把 `.pop-keys`、云机密码、API key、模型缓存或私有数据打进镜像；
  构建上下文模拟确认 `forbidden present: 0`。
- 镜像的复现范围是**纯 Python 参考层 + 证书/验证链路**；**不覆盖**
  SP1 `core`、`groth16`、真实 LLM 的猜测熵 `k`、DeepSeek 端到端会话或云机规模矩阵。
  这些结果的入口在 [`docs/artifact/README.md`](../artifact/README.md) §5，但不在镜像内。
- 宿主复现使用了主检出的预构建 `pop-script`；该二进制不产生证明，也不改变本文结论。

> Python and `cryptography` versions, and the host script
> `scripts/ops/reproduce_artifact.sh` completed with `RESULT: PASS` (13 certificates,
> 17 Python tests). Image size is therefore not reported. The cloud proof results
> (`core`/`groth16`, 6-rule scale, `k`, E2/E3) are repository results, not image
> contents.

不要写「one-command Docker reproduction verified」或给出镜像大小。

## 5. 如何解除

在 Windows 侧启动 Docker Desktop，并在
`Settings → Resources → WSL Integration` 中启用当前发行版，然后：

```bash
docker version                       # 应能同时看到 Client 与 Server
docker build -t pop-artifact .
docker run --rm pop-artifact         # 期望：Ran 42 tests … OK
docker images pop-artifact           # 记录镜像大小，回填 README §2
```

若 `docker build` 卡在拉取基础镜像或 `pip install cryptography`，属网络问题，
不是本仓库的 blocker；可重试或配置镜像源。
