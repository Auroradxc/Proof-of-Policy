## 0. 约定

### 0.1 记号

为避免与框架里的 `M`（工件空间）和论文里的 `M`（模型程序）混淆，本稿用 `Art` 表示工件空间；
它与框架 §2 的 `M` 同义。其余记号：

| 记号 | 含义 |
|---|---|
| `λ` | 安全参数；`negl(λ)` 表示可忽略函数 |
| `N` | 挑战空间；`f` 为接收方贡献的新鲜比特数，`\|N\| = 2^f` |
| `r ← N` | 接收方现场采样的均匀挑战 |
| `Art` | 工件空间（响应文本、工具轨迹、推理输出） |
| `Π` | 策略空间；`π ∈ Π` |
| `R: Π × Art → {0,1}` | 判定关系；`R(π,T)=1` 表示 `T` 满足 `π` |
| `B: N × Art → {0,1}^λ` | 公开绑定函数；PoP 里 `B(n,T)=H("pop-bind-v1"‖u32be(len(n))‖n‖T)` |

| `cert` | 一张证书（框架里的 `c`）；`b(cert)` 为它的公开绑定值 |
| `c` | 定理 C 的**挑战集上界**（每个 transcript 至多覆盖 `c` 个挑战），不是证书 |
| `S` | 对手在看到 `r` 之前预计算/预置的已接受 transcript 集合 |
| `T_V` | 证书 `cert` 所证明的工件（“O 出证时用的那条”） |
| `T_U` | O 实际交付给接收方 `U` 的工件 |
| `x_U` | 用户提交的输入；`M(x)` 为模型程序 `M` 在输入 `x` 上的输出 |
| `IB(n,x)` | 推理侧的输入承诺；PoP 里为 `SHA256(domain‖"input_binding"‖len(n)‖n‖各分量)` |
| `G_rep` | 只要求“U 接受”的重放游戏（即 T3′ 的游戏） |
| `G_del` | 要求“U 接受且 `T_V ≠ T_U`”的交付绑定游戏（框架 D3） |
| `G_del^¬bind` | `G_del` 去掉 D2/B 绑定假设后的版本（用于分离与反例） |
| `A(cert)` | 证书 `cert` 的挑战接受集：`{n ∈ N : Verify(pp,h_π,cert,n)=1}` |
| `W(cert,n)` | 证书在挑战 `n` 下与公开绑定一致的工件集：`{T : B(n,T)=b(cert) ∧ R(π,T)=y(cert)}` |
| `STH` | 透明日志的签名树头（signed tree head） |
| `π_incl` | Merkle 包含证明 |

### 0.2 假设

本稿显式使用以下假设；每条都在证明债里注明“去掉它会怎样”。

| 编号 | 假设 | 来源/说明 |
|---|---|---|
| **A1** | SP1 zkVM 健全性：不能为非确定性执行输出伪造可接受证明 | [`security-model.md`](../security-model.md) §1；官方安全模型 + 审计 + 实测 |
| **A2** | SHA-256 抗碰撞（CR）+ 抗原像 | 标准；ROM 下更强，正文只主张 heuristic |
| **A6** | 规范字节编码单射：不同内容得到不同字节串 | `security-model.md` §1；Python↔Rust 逐字节一致 |
| **D1** | 证书健全性：`Verify=1 ⇒ ∃T': B(n,T')=b(cert) ∧ R(π,T')=y(cert)` | 框架 §3 D1 |

| **IB-bind** | 对任意 `n`，PPT 找 `x≠x'` 使 `IB(n,x)=IB(n,x')` 的概率 `≤ negl(λ)` | 由 A2 + A6 推出 |
| **E-D1** | 策略半与推理半都健全；委托规则有可验证的陪伴证明 | D1 + A1；陪伴证明另有其自身健全性 |
| **F-L** | 透明日志只追加、可公开读；树头签名不可伪造；验证者能取得一致性证明 | 日志假设，非密码学自动成立 |
| **F-O** | 运营方在交付前必须把证书摘要追加到日志（外部义务） | 协议/合同/监管义务，不是密码学结论 |
| **F-S** | 抽样审计对每个违规独立采样，命中即检出 | 审计模型；去掉后见 F3 的精确/近似说明 |

> **总口径**：`negl(λ)` 是一个占位和，展开后是
> `Adv^{sound}_{zkVM} + Adv^{CR}_{SHA256} + Adv^{bind}_{B} + Adv^{sound}_{companion}` 等项之和。
> 每一项在 A1/A2/A6 下可忽略，故和可忽略。**不要把 `negl` 写成信息论界**；
> SHA-256 不是真的随机预言机，ROM 只给 heuristic。

### 0.3 证明口径

1. 所有对手是 PPT；`S` 是多项式大小（框架 §6.1 的“一组”按 `poly(λ)` 读）。
2. “优势”是游戏返回 1 的概率；`f=0` 时 `N` 只有一个元素，记为 `r₀`。
3. 反例都写成“具体方案 + 具体对手 + 具体失败语句”，不只写“缺少条件会出问题”。
4. 不能严格证明的地方进每节末尾的“证明债”，并写明**所需假设**与**论文处置**；
   本稿不留下任何未标注的空位。

## 1. 定理 C：交付绑定（统一 T3）

### 1.1 陈述（框架 §6.1，A1 收口版）

框架现在把两个游戏分开写：

**`G_rep`（重放接受，= T3′ 的 `G_SelPres`）**：对手在见到 `r` 前预置已接受
transcript 集 `S`；`U` 接受当且仅当 `Verify(cert,r)=1`。**引理 C.1** 给出
```
Pr[U 接受] ≤ Σ_{cert∈S}|A(cert)|/2^f ≤ |S|·c·2^{-f}。
```
**`|S|·c·2^{-f}` 界的是 `G_rep` 的接受概率。**

**`G_del`（divergent delivery，框架 D3）**：胜负事件加上 `T_V≠T_U`；
**引理 C.2** 在 D1/D2/B-bind 下给出新鲜证书的 divergence `≤negl(λ)`。
**定理 C** 在 D1/D2/B-bind 下：
```
Adv_del(O) ≤ |S|·c·2^{-f} + negl(λ)。
```
第一项来自 `G_rep` 的重放接受；第二项来自新出证书的 binding 失败。在 D2 下
**`G_del` 的 divergence 本身是 `negl`**，不是 `|S|·c·2^{-f}`。

**`f=0` 的三读法**：`G_rep` 优势 **1**；`G_del`+D1/D2 divergence **`negl`**；
`G_del^¬bind`（非绑定 `B` 的反例）优势 **1**。因此“`f=0` 优势 1”属于
`G_rep`/非绑定 `B`，**不属于 `G_del`+D2**。

形式化版本：

```
设 N 为挑战空间，|N|=2^f，r←N 均匀。
对任意 PPT O，它在看到 r 之前输出集合 S（|S|≤poly(λ)），
每个 cert∈S 满足 |A(cert)|≤c。
G_rep:  Adv_rep(O) ≤ |S|·c·2^{-f}。
G_del:  Adv_del(O) ≤ |S|·c·2^{-f} + negl(λ)   （D1/D2/B-bind 下）。
```

`c` 是**挑战集大小的上界**：一张证书可能对多个挑战都通过 `Verify`（例如空 nonce、
范围 nonce、批量证明），`c` 把这种“一证多挑战”的损失显式写出来；接收方 nonce
协议的 `c=1`。

### 1.2 游戏的形式化

**定义 C.1（交付绑定游戏 `G_del`）**

1. `pp ← Setup(1^λ)`；O 得到 `pp` 与策略 `π`。
2. O 在未见 `r` 之前输出预置集 `S = {(cert_i, T_i)}`（`|S| ≤ poly(λ)`）。
3. `r ← N` 均匀采样，发给 O。
4. O 输出 `(cert, T_U)`。`cert` 可以来自 `S`，也可以是 O 在看到 `r` 之后新出的。
5. U 接受当且仅当
   ```
   Verify(pp, h_π, cert, r) = 1   且   B(r, T_U) = b(cert)。
   ```
6. O 获胜当且仅当 U 接受，且 `T_U ≠ T_V`，其中 `T_V` 是 `cert` 所证明的工件
   （在 D1/D2 下由 `(cert,r)` 唯一确定，见引理 C.2）。

**定义 C.2（重放游戏 `G_rep`）** 与 `G_del` 相同，但胜负事件改为“U 接受”，
不要求 `T_V ≠ T_U`。这就是安全模型 §4.5.4 的 `G_SelPres`，也就是 T3′ 的游戏。

**定义 C.3（无绑定游戏 `G_del^¬bind`）** 与 `G_del` 相同，但去掉 D2/B-bind。
它用于说明：定理 C 的 `negl` 项不是装饰，而是**绑定性假设的价格**。

**挑战接受集与一致工件集**

```
A(cert)    = { n ∈ N : Verify(pp,h_π,cert,n)=1 }
W(cert,n)  = { T ∈ Art : B(n,T)=b(cert) ∧ R(π,T)=y(cert) }
```

- `|A(cert)| ≤ c` 是定理 C 的唯一结构性假设。
- D1 说：`n∈A(cert)` 时 `W(cert,n)` 非空（除 `negl`）。
- D2 说：`W(cert,n)` 至多一个元素（除 `negl`）；这个元素就是 `T_V`。
- 若 `T_U ∈ W(cert,r)` 但 `T_U ≠ T_V`，则 `cert` 的 `b` 在 `B(r,·)` 下有两个原像，
  即 D2 或 B-bind 被攻破。

### 1.3 证明

#### 1.3.1 引理 C.1（重放接受界）

> **引理 C.1** 在 `G_rep` 中，若 O 输出的证书来自预置集 `S`，则
> ```
> Pr[U 接受] ≤ Σ_{cert∈S} |A(cert)| / 2^f ≤ |S| · c · 2^{-f}。
> ```

**证明**：`r` 在 `N` 上均匀，`|N|=2^f`。U 接受意味着
`Verify(pp,h_π,cert,r)=1`，即 `r ∈ A(cert)`。对 `S` 取并界：

```
Pr[U 接受] = Pr[ ∃cert∈S : r∈A(cert) ]
           ≤ Σ_{cert∈S} Pr[r∈A(cert)]
           = Σ_{cert∈S} |A(cert)| / 2^f
           ≤ |S| · c / 2^f。
```

注意：O 在看到 `r` 之后从 `S` 里挑哪一张证书不影响并界；只要 `S` 是预先固定的，
“存在一张命中”的概率就被上式控制。若 `S` 的挑战集重叠，并界仍然成立（只是可能松）。
`T_i` 不进入这个上界：接受事件只要求 `Verify`，`B(r,T_U)=b(cert)` 是其子事件。∎

**紧的部分**：若 `S` 中每张证书的挑战集两两不交、且大小恰为 `c`，则并界取等号：
`Pr = |S|·c/2^f`（只要 `|S|·c ≤ 2^f`）。所以 `c` 这个因子是可达到的，不是装饰。

#### 1.3.2 引理 C.2（新鲜证书的 divergence）

> **引理 C.2** 假设 D1、D2、B-bind。若 O 在看到 `r` 之后**新出**一张证书 `cert ∉ S`，
> 且 U 接受，则
> ```
> Pr[T_U ≠ T_V] ≤ negl(λ)。
> ```

**证明**：U 接受给出

```
Verify(pp,h_π,cert,r)=1    且    B(r,T_U)=b(cert)。
```

由 D1，存在 `T'` 使 `B(r,T')=b(cert)` 且 `R(π,T')=y(cert)`；由 D2，`T_V` 是这个
`T'` 的唯一原像（除 `negl`）。若 `T_U ≠ T_V`，则 `T_U` 与 `T_V` 都是
`B(r,·)` 在 `b(cert)` 下的原像，构成 B-bind 的碰撞（或直接违反 D2）。故该事件
概率不超过 `Adv^{bind}_B + Adv^{D2}`，在 A2/D2 下为 `negl(λ)`。∎

**为什么必须假设 D2/B-bind**：若 `B` 不绑定（例如 `B(n,T)=0^λ`，或 `B` 是有损编码），
O 可以用一张证书证明 `T_V`，交付任意 `T_U≠T_V`，U 的 `B` 检查照样通过，
`T_U ≠ T_V` 的概率可以是 1。见 §1.4 的反例。

#### 1.3.3 定理 C

> **定理 C** 在 D1、D2、B-bind 下，对任意 PPT O，
> ```
> Adv_del(O) ≤ |S| · c · 2^{-f} + negl(λ)。
> ```

**证明**：把 O 的获胜事件按“证书来自 `S`”与“证书是新出的”分成两类。

- **来自 `S`**：U 接受的概率由引理 C.1 控制，`≤ |S|·c·2^{-f}`。
  在这个分支里，即使再加上 `T_U≠T_V`，概率也不会变大；所以它被第一项吸收。
- **新出**：由引理 C.2，`T_U≠T_V` 的概率 `≤ negl(λ)`。

两者取并界：

```
Adv_del(O)
  ≤ Pr[U 接受 ∧ cert∈S] + Pr[U 接受 ∧ cert∉S ∧ T_U≠T_V]
  ≤ |S|·c·2^{-f} + negl(λ)。∎
```

**读法**：第一项是**重放/接受**的界，第二项是**绑定性失败**的界。定理 C 的证明
没有说“重放接受一定导致 divergence”；它只说 divergence 的获胜事件包含在
“重放接受 ∪ 绑定性失败”里。这个并界是有效的，但它对 `G_del` 不是逐点紧的；
紧致性要分两层说，见 §1.5。这个区分是本底稿最重要的精确化点，已列入证明债 C-1。

### 1.4 `f=0`、两种读法与反例

`f=0` 时 `N={r₀}`。分三种读法：

| 读法 | 胜负事件 | `f=0` 优势 | 依据 |
|---|---|---|---|
| `G_rep` | U 接受 | **1** | `S` 中任一张证书永久覆盖 `r₀`；只要 `S` 非空且含一张接受证书 |
| `G_del` + D1/D2/B-bind | 接受且 `T_V≠T_U` | `negl(λ)` | 引理 C.2；divergence 仍需碰撞 |
| `G_del^¬bind` | 接受且 `T_V≠T_U` | **1** | 非绑定 `B` 可把任意 `T_U` 配到 `b(cert)` |

因此，旧版框架 §6.1 的“`f=0` 时优势为 1”在 `G_rep` 与 `G_del^¬bind` 下成立；
在 `G_del` 且同时要求 D1/D2 时，**divergence 的优势实际上是 `negl`**。
这不是说定理“假”，而是说这句话的主语必须是 `G_rep`（或放弃 D2）；
A1 已把框架 §6 改成这个分列写法。
论文若要把“`f=0` ⇒ 交付绑定优势 1”写成定理，必须二选一：

1. 把胜负定义为**重放接受**（T3′ 的读法）；或
2. 明确假设 `B` 不绑定（此时“交付绑定”本来就是不成立的，定理只剩反面教材）。

**非绑定 `B` 的反例（`G_del^¬bind`，`f=0` 或任意 `f`）**

```
令 B(n,T) = 0^λ（常数），Verify 接受任何 b(cert)=0^λ 的证书。
策略 π 可满足；O 诚实地为 T_V 出证（D1 的“存在 T'”仍成立）。
O 交付任意 T_U ≠ T_V。
U 检查 Verify=1 且 B(r,T_U)=0^λ=b(cert)，接受。
O 获胜，概率 1，与 f、|S|、c 全无关。
```

这个反例说明：`negl` 项不能省；没有 D2/B-bind，定理 C 的界不成立。
一个更“像真的”的有损例子是 `B(n,T)=encode(T)`（论文 Proposition `prop:semantic`
的公开特征向量）：多个 `T` 共享同一 `encode`，交付其中一个而证明另一个即可。
常数例子更干净地隔离了“绑定”这一条。

### 1.5 紧致性

**（a）`G_rep` 的紧致性：接收方 nonce 协议达到该界。**

协议：

```
U 采样 r←N，把 r 发给 O；
O 出证，证书公开 b=B(r,T)；
U 验证 Verify(cert,r)=1 且 B(r,T_U)=b(cert)。
```

对固定 `r`，一张证书的挑战集 `A(cert)={r}`，故 `c=1`。O 在见 `r` 之前预置 `S`
（`|S|` 张分别覆盖不同 `r_i` 的证书）。`r` 均匀，命中概率恰好 `|S|/2^f`
（若 `|S|≤2^f`）。这正是定理 C 的界（`c=1`），且并界取等号。
所以**重放接受项是紧的**。

**（b）`c>1` 的紧致性。** 若一张证书覆盖恰好 `c` 个挑战（例如“nonce 落在某个
大小为 `c` 的集合里”），`S` 中每张证书的挑战集两两不交，则
`Pr[U 接受] = |S|·c/2^f`。故 `c` 因子也可达到。若 `c·|S| > 2^f`，界超过 1，
变成平凡界；有意义的 regime 是 `c·|S| ≤ 2^f`。

**（c）`G_del` 的紧致性：必须分层说。**

- 在 `G_rep` 中，接收方 nonce 协议达到 `|S|·2^{-f}`。
- 在 `G_del` + D2 中，同一协议的 divergence 优势是 `negl`，**严格小于**上界；
  上界仍成立，但不是逐点紧的。
- 在 `G_del^¬bind` 中，非绑定 `B` 使“接受 ⇒ 可 divergence”，于是
  `Adv_del = Pr[U 接受] = |S|·c·2^{-f}`，上界紧。

**结论**：定理 C 的紧致性主张应写成“**重放项紧；divergence 项在绑定假设下被
D2 收紧到 `negl`；在非绑定 regime 下整体紧**”。若论文只说“接收方 nonce 协议
达到该界”而不说哪个游戏，审稿人会问“达到的是接受还是 divergence”，
这两个答案在 D2 下相差一个数量级。列入证明债 C-1。

### 1.6 分离：`f=0` 下不存在“公开可验证 + 防重放 + 无接收方参与”

**模型（分离的边界）**

- **公开可验证**：`Verify` 只取公开输入 `(pp,h_π,cert,n)`，不取秘密钥、不取
  验证者的秘密状态；任何人都能重算。
- **防重放**：对任意 PPT O，在“新会话”里让 U 接受一张旧 transcript 的概率
  `≤ negl(λ)`。
- **无接收方参与**：接收侧（终端用户及其代理验证者）不贡献任何新鲜或秘密值；
  等价地，进入陈述的新鲜挑战是固定的 `r=r₀`，`f=0`。
- **无外部机制**：没有全局状态/撤销表/可信时钟/可信硬件/在线监控。

> **命题 C-Sep** 在上述模型里，公开可验证、对接收方的防重放、无接收方参与
> 三条不能同时成立。

> **“接收侧”包括谁**：若终端用户把验证委托给一个代理验证者，而该验证者每会话
> 发新 nonce，且终端用户确实检查这个 nonce，那么 nonce 是**接收侧**参与，
> 不在“无接收方参与”的模型里；若终端用户不持有/不检查这个 nonce，它只能防
> “对那个验证者重放”，不能把交付给终端用户的那条 `T_U` 绑住（见下）。

**证明（一行）**：`f=0` 时 `r` 恒为 `r₀`；一张曾经被接受的 `(cert,T)` 满足
`Verify(cert,r₀)=1` 且 `B(r₀,T)=b(cert)`。`Verify` 与 `B` 都是公开确定谓词，
不随会话变化；O 原样重放 `(cert,T)`，U 再次接受。故防重放失败。∎

**三条腿各自的反面**（说明分离不是“文字游戏”）：

| 放松哪条 | 会发生什么 | 代价 |
|---|---|---|
| 允许接收方贡献 `f>0` | 重放命中概率 `≤2^{-f}`（T3′/定理 C） | 需要接收方在线、贡献 nonce |
| 允许接收侧（含代理验证者）每会话发新 nonce | 重放命中概率 `≤2^{-f}` | 接收侧参与；若终端用户不持有该 nonce，交付绑定仍不成立 |
| 允许验证者有秘密状态/撤销表 | 旧证书可被标记为已用 | 不再是“公开可验证”的 stateless 谓词；需要全局状态 |
| 允许可信硬件/时钟/监控 | 可强制新鲜性或签发 | 引入外部信任根 |

**与“验证者 nonce”的区别（必须写清）**：现有 PoP 的 `n` 是**验证者**签发的，
不是终端接收方。验证者 nonce 能防“对同一个验证者重放”，但**不绑定交付给终端用户
的那条 `T_U`**：O 可以拿一份对 `T_V` 的证书给验证者看，把 `T_U` 交给终端用户。
这就是论文 Proposition `thm:gap` 的 residual gap，也是论文 Table `tab:wp4-capability`
里“End user”一行要求 `f>0` 的原因。命题 C-Sep 的“无接收方参与”正是把这个区别
形式化：**接收方**的新鲜量才是交付绑定的资源；验证者的 nonce 不是。

**分离的模型边界（证明债 C-7）**：若允许“验证者保存已用证书集合”，重放可以被
挡住，但那时 `Verify` 不再是公开 stateless 谓词；若允许“可信时钟/硬件”，那是
外部机制。分离只对“stateless 公开验证 + 纯密码学”成立，不能写成“任何系统都
不可能防重放”。

**`c>1` 的新增部分（相对 T3′）**

T3′ 的证明隐含“一张证书只覆盖一个挑战”：`Verify(r,rec)` 通过要求
`rec` 绑定的挑战等于 `r`，命中概率 `2^{-f}`。定理 C 把“一张证书可能覆盖
`c` 个挑战”显式化，得到 `c` 倍损失。具体来源：

1. **空 nonce / nonce 被忽略**：`A(cert)=N`，`c=2^f`。界变成 `|S|`；`f=0` 时
   就是 1。这不是假想：`circuits/types/src/lib.rs` 的注释明文说空 nonce
   “不提供任何重放防护”，它是当前 API 的合法输入。
2. **范围/前缀 nonce**：证书绑定“`n` 落在某个大小为 `2^{f-f'}` 的集合里”，
   则 `c=2^{f-f'}`，损失 `2^{-f'}`；`f'` 是真正被钉住的新鲜比特。
3. **批量/聚合证明**：一张证书覆盖 `m` 个请求，`c=m`；复用同一张证书的代价
   线性于 `m`。
4. **`c` 不可乘时界变平凡**：若 `c·|S| > 2^f`，上界 `>1`，没有信息量。
   论文要写明“有意义的 regime 是 `c·|S| ≤ 2^f`”。

**与 T3′ 的关系一句话**：T3′ 是 `c=1`、`f>0` 的分支；定理 C 补上 `c>1`
的乘性损失与 `f=0` 的分离。**新增的是账本，不是新的猜测界**；这与框架 §14
的“不要包装标准界”一致。

**实验对应**：`docs/plan-bhv.md` 的 E5 / P1-08 计划测“`f=0` 重放成功、
end-user `f>0` 失败”。本稿的 `G_rep` 就是该实验的游戏；`c>1` 的实验尚无
（列入证明债 C-8）。

## 2. 定理 E：组合的必要条件

### 2.1 陈述与复合陈述

框架 §8.1 的陈述（原文冻结）：

> 若
> 1. `CS_policy` 与 `CS_infer` 都健全；
> 2. 两半绑到**同一个**新鲜 `n`；
> 3. 两半说的是**同一条** `T`（验证方现场重算 `response_binding`）；
> 4. `CS_infer` 绑到**用户提交的 `x_U`**；
> 5. 策略半 `delegated` 为空（或陪伴证明被合取）；
>
> 则复合证书推出 `∃T: R(π,T) ∧ T=M(x_U) ∧ b=B(n,T)`。

形式化版本（与框架 §8.1 等价，但把 `x` 显式量化）：

```
∃ T ∈ Art, x ∈ X :
    R(π, T)            （策略半）
  ∧ T = M(x)           （推理半；M 由 vkey_infer 承诺）
  ∧ x = x_U            （输入就是用户提交的那条）
  ∧ b = B(n, T)        （两半共享的公开绑定）
```

它与框架的 `∃T: R(π,T) ∧ T=M(x_U) ∧ b=B(n,T)` 等价：把 `x=x_U` 代进
`T=M(x)` 即得。五个必要条件记作：

- **C1（两半健全）**：`CS_policy` 与 `CS_infer` 都满足 D1；委托规则有可验证的
  陪伴证明。
- **C2（同一 `n`）**：两半绑到同一个新鲜挑战 `n`。
- **C3（同一 `T`）**：验证方由送达的 `T_U` 现场重算 `B(n,T_U)`，要求两半的
  `b` 都等于它。
- **C4（绑 `x_U`）**：推理半的 `input_binding` 等于 `IB(n,x_U)`（由用户提交的
  输入现场重算）。
- **C5（`delegated` 空/陪伴）**：策略半的 `delegated` 为空，或每条委托规则
  都有验证通过的陪伴证明且其公开实例含 `encode(T_U)`。

其中 `n` 是新鲜的、两半共用的挑战；`x_U` 在出证前固定；`M` 是 `vkey_infer`
所承诺的**那一个**程序，不是“存在某个模型”。`b` 是复合证书顶层的
`response_binding`，验证方由送达的 `T_U` **现场重算**并与两半比对。

### 2.2 验证器检查与证明

把复合验证写成 `V_comp(C, x_U, T_U)`，检查七项；括号里是
`policydsl/proofs/compose.py::verify_composite` 的对应步骤：

1. **形状**：恰好一份 policy + 一份 inference，不多不少（步骤 1）。
2. **证明文件承诺**：两份证明文件的 SHA-256 与证书声明一致（步骤 2）。
3. **两半都有效**：各自 `Verify` 通过，公开值解出的 outcome 与证书记录一致，
   vkey 哈希一致（步骤 3）。
4. **键分离与期望 vkey**：`vkey_policy ≠ vkey_inference`；给了 `expected_vkeys`
   时逐一匹配（步骤 4）。
5. **域/模式**：policy 半是 `public` 模式；inference 半是 `infer` 域（步骤 5）。
6. **同一 `n`、同一 `T`**：复合证书的 `nonce` 是两半共用的；`response_binding`
   四方一致：`composite`、policy 公开值、inference 公开值、由送达 `T_U`
   **现场重算**的 `B(n,T_U)`（步骤 6）。
7. **模型与输入**：`model_hash` 等于 `vkey_infer` 承诺的模型规格；
   `input_binding` 等于由输入重算的 `IB(n,x)`（步骤 7；**当前实现绑的是
   `input_from_response(T_U)`，不是 `x_U`，见 §2.7**）。

**引理 E.1（两半各自的结论）** 在 D1 下，若两半都验证通过，则存在
`T_p, x_i, T_i` 使

```
R(π, T_p) ∧ B(n, T_p) = b_p
T_i = M(x_i) ∧ IB(n, x_i) = ib ∧ B(n, T_i) = b_i
```

除 `Adv^{sound}_{pol} + Adv^{sound}_{inf}`。

**引理 E.2（同一 `T`）** 若 `n` 相同、`b_p = b_i = B(n,T_U)`，且 B-bind，
则 `T_p = T_i = T_U` 除 `negl(λ)`。

**证明**：`B(n,T_p)=B(n,T_i)=B(n,T_U)`。若三者中有两个不同，即 B-bind 的碰撞。
由引理 E.1 的 `T_p,T_i` 存在；故除 `negl` 外三者相等。∎

**引理 E.3（绑到 `x_U`）** 若 `IB(n,x_i)=IB(n,x_U)` 且 IB-bind，则 `x_i=x_U`
除 `negl(λ)`。

**引理 E.4（`delegated` 空/陪伴证明）** 若策略半的 `delegated` 为空，则电路
判定的就是完整的 `R(π,·)`；若 `delegated` 非空，则必须对每条委托规则验证
陪伴证明，且其公开实例包含 `encode(T_U)`，才能把 `R(π,T_U)` 补全；
缺少陪伴证明时验证方必须 fail closed。

**定理 E** 在 E-D1（两半健全）、同一 `n`、同一 `T`、`x_U` 绑定、
`delegated` 空或陪伴证明被合取、vkey/模型被承诺的条件下，

```
V_comp(C, x_U, T_U)=1
  ⇒  ∃T,x: R(π,T) ∧ T=M(x) ∧ x=x_U ∧ b=B(n,T)
  ⇔  ∃T: R(π,T) ∧ T=M(x_U) ∧ b=B(n,T)。
```

**证明**：由引理 E.1 得 `T_p` 与 `(x_i,T_i)`；由引理 E.2 得
`T_p=T_i=T_U`；由引理 E.3 得 `x_i=x_U`；由引理 E.4 得 `R(π,T_U)` 是完整的
（或由陪伴证明补全）。取 `T=T_U` 即得复合陈述。误差为各引理的 `negl` 之和。∎

**关于“新鲜 `n`”**：定理 E 本身是**语句蕴含**，不是重放定理；`n` 的新鲜性
保证两半属于同一会话、防止跨会话拼接。重放由定理 C 处理。若 `n` 可重用，
一份旧的复合证书会被再次接受，但那是 C 的问题，不是 E 的蕴含失败。
论文要把这两层分开写。

**逐条说明**

1. **不同 `n`**：这条反例的关键不是“两半各自假”，而是“两半各自真、合起来
   不成立”。`T_good` 的策略证明是真的，`T_bad` 的推理证明也是真的；缺的是
   “它们说的是同一次请求/同一条输出”。若验证方用复合证书顶层的 `n` 去重算
   两半的 `b`，至少有一半对不上；所以同一 `n` 是**验证方必须检查**的条件，
   不能只写在证书里。
2. **未绑 `x_U`**：这是论文 §7.5 最关心的一条。推理半只证
   `∃x: T=M(x)`，不证 `x=x_U`；对手可以挑一个“好输入”出证，再把它和策略半
   拼起来。结论里的 `T=M(x_U)` 不成立。当前实现把输入定义为
   `input_from_response(T_U)`（由响应确定性导出），所以它证的是
   `T=M(derive(T))`，不是 `T=M(x_U)`；这是**实现与论文契约的差距**，见 §2.7。
3. **`delegated` 非空**：`delegated` 非空意味着策略里有规则**没被这份证明判定**
   （P2-9 语义规则）。若验证方把 `passed=true` 读成“合规”，就是把“没判”
   当“判过了”，正是 P0-1 的形态。当前 `verify_composite` 在 `delegated` 非空时
   返回 `satisfied=False`，是 fail closed 的正确行为；反例针对的是去掉这条检查
   的验证方。若合取陪伴证明，还要要求它的公开实例包含 `encode(T_U)`，
   否则陪伴证明可能说的是另一条响应。
4. **两半说不同 `T`**：即使 `n` 相同，`B(n,T_good)` 与 `B(n,T_bad)` 也不同；
   若验证方只逐半检查、不把两半的 `b` 与送达 `T_U` 的现场重算值做四方比对，
   两份真证明可以拼成一张假复合证书。当前 `check_response_binding` 比较
   `composite / policy / inference / response` 四个值，正好堵这条。
5. **两半不健全**：这不是“少写一个检查”，而是“整个归约的地基没了”。
   策略半若能为 `T⊭π` 出可接受证明，组合层的合取只能保证“两半都说了它们
   说的话”，不能保证“话是真的”。推理半同理。误差项必须显式写出
   `Adv^{sound}_{pol}+Adv^{sound}_{inf}`；不能把它们藏进 `negl` 而不声明。

### 2.4 附加实现条件：vkey 分离

五个逻辑条件之外，`verify_composite` 还要求
`vkey_policy ≠ vkey_inference`（`compose.py` 步骤 4）。这不是逻辑必要条件，
而是“哪一半是哪一半”的**可判定性**条件：若两半可以由同一个程序产生，
攻击者可以把一份策略证明放进推理槽（或反之），逐 half 检查全过，
但 `T=M(x_U)` 根本没有被证明。代码在 `compose.py:361` 拒绝同 vkey；
测试 `test_same_vkey_for_both_halves_is_rejected` 覆盖。论文 §7.5 的“short
contract”若只写“expose T + bind x”，还漏了这一条和“期望 vkey”，应一起写进
契约（证明债 E-5）。

### 2.7 当前实现的差距：`x_U` 绑定

这是本稿在只读代码时发现的最实质的一条，必须写进论文/实现计划：

- `verify_composite` 步骤 7 计算
  ```
  want_input = infer.input_binding(composite.nonce,
                                   infer.input_from_response(response))
  ```
  （`policydsl/proofs/compose.py:412`）。
- `input_from_response` 把**送达的响应** `T_U` 哈希成模型输入
  （`policydsl/proofs/infer.py:103-112`）。
- 因此当前组合证明的是
  ```
  ∃ x : x = derive(T_U) ∧ T_U = M(x)
  ```
  这是一个**确定性关系**，不是论文 §7.5 要的 `x = x_U`。
- 若用户提交的 `x_U` 不等于 `derive(T_U)`，当前组合证书不能推出
  `T_U=M(x_U)`；它只推出“模型在由输出反推的输入上算出了这个输出”。
- 测试 `test_input_from_another_response_is_rejected` 证明“换响应会被拒”，
  但它检查的是 `derive(T)` 的一致性，不是“用户提交的输入”的一致性。

**闭合方式（实现债，不是本稿能改的代码）**：

1. 证书公开值加入 `x_U`（或其承诺 `com(x_U)`），推理陈述改为
   `T=M(x_U) ∧ com(x_U)=c_x`；
2. 验证方由 `x_U`（或开示）现场重算 `IB(n,x_U)`，与推理半的
   `input_binding` 比对；
3. `x_U` 必须在出证前固定（或先承诺），否则对手可以看 `n` 再挑输入；
4. 若 `x_U` 需要保密，用承诺 + 开示/零知识证明，而不是把明文放进公开值。

在这一条闭合之前，定理 E 只能以“`x` 是 `derive(T)`”的弱形式写进论文；
不能声称已经证了用户提交输入的绑定。列入证明债 E-1（高）。

> **A1 的边界**：A1 只做理论收口——把“当前实现只证弱形式（E-1）”写清，
> **不在 A1 里实现 E-1**。实现 `x_U` 绑定是后续工作项（公开值加 `x_U`/承诺、
> 验证方现场重算 `IB(n,x_U)`）。论文在实现闭合前只能写弱形式。

## 3. 定理 F：签发完整性

### 3.1 陈述

框架 §9 的三件事，本稿形式化为 F1/F2/F3：

- **F1（不可能性）**：没有外部机制强制签发时，任何方案都不能对任意运营方
  保证 D7（issuance completeness）；一个“什么都不做”的 withholding 对手
  以概率 1 获胜。
- **F2（条件充分性）**：若运营方在交付前必须把证书摘要追加到只追加、可公开读的
  透明日志，日志条目绑定到被交付的 `T`（或含交付回执），验证者检查包含证明，
  则在日志假设 + 外部义务下，D7 对**被交付的工件**成立。
- **F3（抽样检出）**：在每个违规独立采样、命中即检出的模型下，检出概率为
  `1-(1-p)^m`；无放回抽样有精确的超几何形式。

D7 的原文是“每个被交付的工件 `T` 都存在一张有效证书”。注意它是对
**被交付工件**的 liveness 性质，不是对任意运营方行为的保证；F1 说的正是
这个区别。

### 3.2 不可能性

**定义 F.1（withholding 游戏 `G_issue`）**

1. 运营方 O 与用户 U 交互；U 可能收到工件 `T_1,…,T_m`。
2. O 可以选择调用 `Prove` 并发布证书，也可以不调用。
3. O 获胜当且仅当存在一个被交付的 `T_i`，它没有有效证书
   （即不存在 `cert` 使 `Verify(cert,n_i)=1` 且 `B(n_i,T_i)=b(cert)`）。

> **命题 F1** 对任意证书方案 `CS`，存在 PPT 对手 O 使
> `Pr[G_issue(O)=1]=1`。

**证明**：O 按正常流程生成/交付 `T`，但从不调用 `Prove`、从不发布证书。
验证者一侧没有任何证书；对任意候选 `cert`，`Verify` 都没有被调用的输入。
因此“存在有效证书”为假，O 获胜。这个策略不需要攻破任何密码学假设，
也不需要与验证者交互；它是**不行动**。∎

**为什么这不是实现的缺陷**：证书方案的算法是“如果被调用，就产生可验证的
对象”；它不能强制运营方调用。缺少证书的验证者视图与“根本没有工件”的视图
相同：两者都是空 transcript，没有区分器。论文 §7.4 的
“indistinguishable from a provider with nothing to certify”就是这句话。

**边界**：

- 若协议规定“没有证书就不能交付”，运营方仍可以选择**不提供服务**；
  这是 liveness 的另一形态，不是 D7 的密码学保证。
- 可信硬件/可信监控/法律义务可以强制或惩罚签发，但它们是外部机制，
  F1 的模型明确排除。
- F1 是**不可能性/边界结果**，不是“我们的方案不健全”；它把论文的
  “open problem”变成“密码学层单独做不到”的精确陈述。

### 3.3 充分性

**构造（透明日志 + 包含证明）**

- 日志 `L` 是只追加 Merkle 树；日志公钥 `pk_L`；树头
  `STH_t = Sign_{sk_L}(root_t, size_t, t)`。
- 运营方在交付 `T` 前：
  1. 出证 `cert ← Prove(pp,π,T,n)`；
  2. 计算叶子 `d = H(canonical(cert))`；
  3. 把 `d` 追加到 `L`，取得包含证明 `π_incl`；
  4. 交付 `(T, cert, π_incl)`。
- 接收方/验证者检查：
  1. `Verify(pp,h_π,cert,n)=1`；
  2. `B(n,T)=b(cert)`；
  3. `π_incl` 证明 `d` 在某个由 `pk_L` 签名的 `STH` 之下；
  4. （可选）`STH` 与上次见到的一致（只追加/一致性证明）。

> **定理 F2** 在以下三条外部前提与日志假设下成立：
> **F-1（外部义务 F-O）** 运营方在交付前必须追加日志；
> **F-3（日志条目绑定被交付的 `T`）** 条目含 `B(n,T)` 或可核对的交付回执；
> **F-4（抽样框是“交付”而非“日志”）** 审计样本包含被交付工件；
> 以及 F-L（只追加、可公开读、树头签名不可伪造）、A2（CR）。
> 若验证者接受 `(T,cert,π_incl)`，则 `cert` 是 `T` 的有效证书且已进入日志；
> 因此 D7 对**被交付且被验证者接受**的工件成立。

**证明**：

1. 验证者接受 ⇒ 包含证明验证通过 ⇒ `d` 是 `STH` 覆盖的叶子；
2. 只追加 + CR ⇒ `d` 在该 `STH` 之前已被追加，且没有被删除/改写；
3. `d=H(canonical(cert))`，且 `cert` 含 `b(cert)=B(n,T)`（或含绑定 `T` 的
   交付回执）⇒ 日志里的证书就是为 `T` 的那张；
4. F-O ⇒ 运营方在交付前执行了追加；若它跳过，验证者的包含检查失败
   （若验证者强制要求），或审计者通过“交付记录 vs 日志”发现缺失；
5. 所以存在有效证书，D7 成立。∎

**关键限定（否则 F2 是假的）**：

- **日志条目必须绑定到被交付的 `T`**。只记 `H(cert)` 还不够，除非 `cert`
  的公开值里有 `B(n,T)` 或验证者能由 `T` 重算；若 `T` 是私有的，日志条目
  应含一个交付回执（例如 U 签名的 `H(T)` 或 `B(n,T)`），否则运营方可以
  记一张“另一条 `T`”的证书，交付另一条。
- **外部义务 F-O 不是密码学结论**。没有它，F1 适用；日志只能让“没记”
  在事后可检测，不能强制“记”。
- **日志的 split-view**：恶意日志可以给不同验证者看不同的 `STH`。需要
  gossip/一致性证明/监控；否则“只追加”只是对单个视图的承诺。列入 F-2。
- **可用性**：日志不可用时验证者无法检查包含；需要“最终可用”或延迟验证的
  liveness 假设。

**与“证明为真”的区别**：F2 只保证“证书存在且被记录”，不保证 `passed=true`
或策略合规。一张如实记录违规的证书同样是真证书；这与 L7/L8 的
`RESULT` 与 `合规` 分开呈报是同一口径。

### 3.4 抽样审计的检出概率

**模型**：有 `m` 个违规（被交付但没有有效/已记录证书的工件）；审计者对每个
违规独立地以概率 `p` 采样；一旦采到就检出。

**推导**：

```
Pr[漏掉第 i 个违规] = 1-p
Pr[漏掉全部 m 个]   = (1-p)^m        （独立性）
Pr[至少检出 1 个]   = 1 - (1-p)^m。  （互补）
```

- `m=0` 或 `p=0` 时概率为 0；`p=1` 时为 1。
- 小 `p` 时 `1-(1-p)^m ≈ 1-e^{-pm}`；期望检出数（含重复）为 `pm`。
- 给定置信度 `1-δ`，需要
  ```
  m ≥ ln(δ) / ln(1-p) ≈ ln(1/δ) / p。
  ```
  例：`p=0.01`，`m=100` ⇒ `1-0.99^100 ≈ 63.4%`；`m=458` ⇒ `≈99.0%`；
  `p=0.1`，`m=44` ⇒ `≈99.0%`。

**无放回的精确形式**：若从 `N` 个交付中均匀抽 `s` 个（`s=pN`），违规 `m` 个，

```
Pr[检出] = 1 - C(N-m, s) / C(N, s)。
```

当 `N≫m,s` 时退化为 `1-(1-p)^m`。论文若写 `1-(1-p)^m`，应注明
“独立采样/有放回”或“`N` 很大时的近似”；否则审稿人会问抽样设计。

**必须写清的四个前提**（否则公式是空转）：

1. **抽样框必须包含“被交付的工件”**，不能只抽“已记录的证书”。只抽日志时，
   withholding 对手根本不进样本，检出率为 0；这正是 F1 的形态。
2. **独立性**：违规可能同源（一个根因导致一批），此时 `m` 不是独立事件数，
   `1-(1-p)^m` 会高估检出率；应写成“独立可检事件数”。
3. **命中即检出**：审计者要能判定“这个交付没有有效证书”；若需要运营方配合
   开示，检出会打折。
4. **检出 ≠ 阻止**：抽样只提高被发现概率；是否阻止取决于罚则/经济激励，
   本稿不建模（证明债 F-5）。

**这条公式的定位**：它是标准的互补概率，不是新定理；它的价值是把论文 §7.4
的“sampling audits”从一句话变成可算的曲线，并暴露“样本框必须是交付而非日志”
这个常被忽略的前提。与框架 §14 的“标准（必须引用）”一致。

### 3.5 与 paper §7.4 Coverage 的对应
