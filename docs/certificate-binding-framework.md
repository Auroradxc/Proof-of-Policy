> **状态：维护中的设计底稿（2026-11-01 立）。** 本文件回答一个问题：
> **一张合规证书到底绑住了什么、又藏住了什么？** 它把散落在

>
> **与其他文档的分工**：

## 0. 一句话

> 证书的绑定力 = 它**公开承诺的、对手无法预先选择的那部分比特**；
> 响应侧看熵 `k`，请求侧看新鲜度 `f`，**策略侧看策略的猜测熵 `k_π`（或盐）**。
> 三者共享同一个三难：**binding、hiding、public verifiability，低熵时至多取二。**

## 1. 为什么需要一个框架

当前项目里，同一条数学事实被拆成了三处互不相认的叙述：

| 现有位置 | 说的东西 | 缺的那一半 |
|---|---|---|
| `security-model.md` §4.5 T1 | `response_binding = H(n,T)` 是猜测-验证 oracle；`k` 不足时重执行恢复 `T` | 只讲**响应**，没讲策略 |
| `security-model.md` §4.5 T3′ | 空 nonce 时重放优势为 1；`f` 位新鲜性给出 `|S|·2^{-f}` | 只讲**请求**，没讲策略 |
| `security-model.md` §4.6 P-PP | 策略文本是 witness；`policy_hash` 公开；需要签发权威 | 没讲 **`policy_hash` 本身也是公开可重算的绑定**，因而也可被枚举 |

第三个面的缺失是实质性的：`policy_hash = SHA256(canonical(π))` 与
`response_binding = SHA256(dom‖n‖T)` **是同一个数学对象**——一个公开、可离线重算的
秘密函数。既然响应侧会因为 `k_T` 不足而泄露 `T`，策略侧就会因为策略空间小
而泄露 `π`。这一点在论文 Table `tab:wp4` 第 1 行「policy text 本身已关闭」里被漏掉了：
**关闭的是文本，不是哈希**。

框架的目标不是增加一条新原语，而是让这三件事在同一组定义下可比较、可证明、可测量。

## 2. 记号

| 记号 | 含义 |
|---|---|
| `λ` | 安全参数 |
| `M` | 工件空间（响应文本、工具轨迹、推理输出） |
| `Π` | 策略空间（DSL 可表达的全部策略包） |
| `N` | 挑战空间，`|N| = 2^f` |
| `R: Π × M → {0,1}` | 判定关系；`R(π,T)=1` 表示 `T` 满足 `π` |
| `H` | 哈希；证明中按随机预言机（ROM）论证，正文写明 heuristic |
| `B: N × M → {0,1}^λ` | 公开绑定函数 |
| `Z` | 对手侧信息（prompt、模型、解码参数、部署上下文） |
| `Guess(X|Z)` | `max_A Pr[A(Z)=X]`，即平均条件猜测概率 |
| `k_X` | `-log₂ Guess(X|Z)`，猜测熵 |

## 3. 定义（D1–D8）

### D1. Certificate scheme

一个策略证明方案是四元组 `CS = (Setup, Prove, Verify, B)`：

- `Setup(1^λ) → pp`；
- `Prove(pp, π, T, n) → c`，`c` 的公开值含 `h_π`、`b = B(n,T)`、`y = R(π,T)`；
- `Verify(pp, h_π, c, n) → {0,1}`；
- **完整性**：`R(π,T)=1` 且 `c ← Prove(pp,π,T,n)` ⇒ `Verify=1`；
- **健全性**：对任意 PPT `A`，
  ```
  Pr[ Verify(pp,h_π,c,n)=1 ∧
      ¬∃T': B(n,T')=b(c) ∧ R(π,T')=y(c) ]  ≤  negl(λ)
  ```
  即「接受 ⇒ 存在一条与公开绑定一致、且满足策略的工件」。

> PoP 的 `Prove` 是 SP1 guest；`B` 是 `response_binding`；`h_π` 是 `policy_hash`。
> 健全性归约到 SP1 健全性 + SHA-256 抗碰撞（见 `security-model.md` §4 主定理）。

### D2. Challenge binding

若对任意 PPT `A`，
```
Pr[ A(pp) → (c,n,T') : Verify=1 ∧ B(n,T')=b(c) ∧ T' ≠ T ] ≤ negl(λ)
```
则称方案对挑战 `n` 是绑定的。它在 D1 健全性之上再加一条：**公开值里的 `b`
唯一的原像就是被证明的那条 `T`**（由 `B` 的抗碰撞与长度前缀单射保证）。

### D3. Delivery binding game

参与方：运营方 `O`（不可信）、接收方 `U`、验证者 `V`。

1. `U` 采样 `r ← N`，把 `r` 发给 `O`；
2. `O` 输出 `(c, T_U)`，把 `T_U` 与 `c` 交付给 `U`；
3. `U` 接受当且仅当 `Verify(c,r)=1` 且 `B(r,T_U)=b(c)`。

`O` 获胜当且仅当 `U` 接受，但 `c` 所绑定的工件 `T_V`（`O` 出证时用的那条）`≠ T_U`。
记 `Adv_del(O) = Pr[O 获胜]`。这就是 **divergent delivery** 的游戏化。

### D4. Leakage profile

把验证者视图拆成三路：

```
V = ( L_pub(π,T,n),  L_proof(w),  L_side )
```

- `L_pub`：证书公开值（不含证明工件）；
- `L_proof(w)`：证明工件对见证 `w=(π,T,trace)` 的泄露；witness-hiding 时记为 `⊥`；
- `L_side`：对手的侧信息 `Z`。

### D5. Policy disclosure 与 D-privacy（完整游戏）

令 `D: Π → 𝔻` 是**披露函数**（验证者被允许知道的那部分策略）。D-privacy 的
完整不可区分游戏如下（对手是**验证者** `V`，不是运营方 `O`）：

```
游戏 Priv_{CS,D}(λ):
  1. 挑战者 C 运行 pp ← Setup(1^λ)，把 pp 交给对手 A。
  2. A 输出 (π₀, π₁, T, n, aux)，要求：
       D(π₀) = D(π₁)；
       T ∈ M，n ∈ N；
       R(π₀,T) = R(π₁,T)（同一条工件、同一判定）；
       aux 是辅助输入（部署上下文、候选策略库等）。
     任一条件不满足则 C 中止，该查询不计入优势。
  3. C 采样 b ← {0,1}，运行 c ← Prove(pp, π_b, T, n)，
     把 View_b = (L_pub(π_b,T,n), L_proof(π_b,T,n), L_side) 交给 A。
  4. A 输出 b' ∈ {0,1}。
  5. 若 b'=b，A 获胜。
```

优势 `Adv_{CS,D}(A,λ) = |2·Pr[A 获胜] − 1|`。方案是 `D-private` 的，若对任意
PPT `A`，`Adv_{CS,D}(A,λ) ≤ negl(λ)`。

> **工件必须固定（或 public T-view 相同）。** 证书公开值含 `b=B(n,T)`；若
> `T₀≠T₁`，验证者算一次 `B(n,T₀)`、`B(n,T₁)` 就能区分，这与策略隐私无关。
> 因此游戏固定**同一条** `T` 与**同一个** `n`；等价地允许 `T₀,T₁` 不同，但要求
> 它们的 public T-view（`b`、`response_commitment`、`trace_root` 等所有公开的
> `T` 派生值）相同。旧版 D5 写“任意同判定 `T₀,T₁`”是读法缺陷，已由本版修正。
> 不同 `T` 的区分归响应侧定理 A/B。

### D6. Composition

两个方案 `CS_policy`（证 `R(π,T)`）与 `CS_infer`（证 `T=M(x)`）合成后，
复合陈述是
```
∃T: R(π,T) ∧ T=M(x) ∧ x=x_U ∧ b=B(n,T)
```
其中 `x_U` 是**用户提交的输入**。

### D7. Issuance completeness

方案是签发完整的，若每个被交付的工件 `T` 都存在一张有效证书。
这是「provider 可以不签发」这一覆盖问题的形式化。

### D8. Trace binding

把工具轨迹 `R` 当作工件 `T` 的一个特例：回执链的 `seq/prev/digest`
结构由电路保证，签发者身份由链下 Ed25519 验签承担，截尾由 `ToolSeal` 堵。
它是 D1/D2 在「工件 = 轨迹、绑定 = 链尾摘要」上的实例。

### D9. PV-1（公开证明验证，弱）

`Verify` 是一个 PPT 算法，输入只有公开量 `(pp,h_π,c,n)`（及公开参数），
**没有秘密密钥、没有秘密状态**；完整性成立，D1 健全性成立。它只保证
“存在某个见证满足电路”，不要求验证者能独立重算 `β`。

### D10. PV-2（公开重算绑定，强；三难统一用此定义）

存在一个 PPT 算法 `E`，输入只有公开量 `(pp,X)`（`β` 随机化时再加公开随机带
`ρ`），满足 `E(pp,X)=β(X)` 对所有 `X∈𝒳`；并且 `Verify` 的接受蕴含
`b(c)=E(pp,X)` 对“被证明的那条 `X`”成立（或验证者在拿到开示 `X` 后能自己用
`E` 检查）。直观：**`β` 没有秘密密钥，任何人可离线重算**。

> PV-1 与 PV-2 的区分不是文字游戏：带密钥 `β_s(X)=H(s,X)` 可以保留 PV-1
> （ZK 证明仍可公开验证），但丢失 PV-2（没有 `s` 无法重算）。**定理 A 的三难
> 是 PV-2 的陈述，不是 PV-1 的陈述。** 响应侧 `b=H(pop-bind-v1‖n‖T)` 满足
> PV-2；加盐策略承诺不满足。

## 4. 定理 A：BHV 三难（本框架的承重墙）

> **现状**：论文 §3 的“one spine, two sides”只覆盖响应与请求。
> 本定理把它扩成**三个面**，并给出策略侧的实例。

### 4.1 陈述（A1 收口版；PV-2 口径）

**前提（A-RO / guess-tight）.** `β` 的实现是 `β_ρ(X)=H(DOM‖ρ‖X)`，其中
`H` 建模为随机预言机，`ρ` 是**公开**随机带（确定性 `β` 时为空串），与 `X`、
`Z` 独立并随 `b` 发布，`DOM` 是固定域分隔串。`β` 的每次求值是一个候选 `X`。
**`id`、`encode` 等把 `X` 直接交出的公开函数不满足此假设**；它们落在有损制式
（`Guess(X|Z,β(X))`，见 §4.1.2）。

设 `X` 是被绑定的秘密（`T` 或 `π`），`Z` 是对手侧信息，`q` 是**对手对 `β`
的求值次数上限**（不是时间；对手可计算无界），`q≥1`，最终输出计入一次求值。

1. **命题 A.1（公开绑定）**：在 (A-RO) 下，
   ```
   Pr[ A^β(Z, β(X)) = X ]  ≤  q · Guess(X|Z) + negl(λ) = q · 2^{-k_X} + negl(λ)
   ```
   因此以优势 `ε` 隐藏 `X` 的**充分条件**是
   ```
   k_X  ≥  log q + log(1/ε)
   ```
   （这是上界认证的充分条件，不是由 A.1 单独推出的必要条件；见
   Remark A.3′ 与 §4.1.2。）
2. **命题 A.2（带密钥绑定）**：若 `β_s(X)=H(s,X)`，`s` 只由指定方持有且不进
   公开值，且对手**没有** `β_s` 求值 oracle，则
   ```
   Pr[A(Z,b)=X]  ≤  Guess(X|Z) + negl(κ)
   ```
   即**去掉 `q` 放大**：`k_X` 不必达到 `log q+log(1/ε)`，只需
   `Guess(X|Z)≤ε`。**正确读法不是“`k_X=0` 也可以隐藏”**——`k_X=0` 时
   `Guess=1`，`Z` 已确定 `X`，任何 `β` 都救不了。带密钥形式的代价是
   **PV-2 丢失**（定义 D10）：没有 `s` 无法离线重算 `β_s`。
3. **命题 A.3（条件性三难）+ Remark A.3′**：固定 `λ,ε>0`、`q≥1`。设
   `k_X < log q + log(1/ε)`，且 `X` 在其候选集上（近似）均匀（或隐藏声明由
   公开值上界认证）。考虑满足以下形状的方案类 `𝒞`：绑定是 PV-2（D10）；
   隐藏是精确恢复；`β` 是 guess-tight（A-RO）。则 `𝒞` 中不存在同时满足
   binding、hiding、PV-2 的方案；等价地**三者至多取二**。

> **Remark A.3′（分类，不是不可能性定理）**：A.3 是 **Proposition + Remark**，
> 不是“我们证明了三难定理”。它的前提是 `𝒞` 的定义（PV-2、精确恢复、
> guess-tight、均匀/上界认证）；它没有证明“在任意验证模式下三者互斥”。
> 逃逸真实存在：PV-1 + 带密钥 `β` + ZK（信任转移给权威）、TEE/attestation、
> 交互式/指定验证者、高熵 `X`、放宽为不可区分隐藏、以及 `k_X=0`（隐藏本来
> 就失败）。偏斜分布下 `q·Guess` 可能远大于前 `q` 个候选的质量，A.3 只能读作
> “这个上界认证不了 ε-hiding”，不是“实际隐藏失败”。

#### 4.1.1 `n` 公开 / `n` 保密（定理 A 的两制式）

定理 A 的 `X=T`、`β=B(n,·)` 有两种制式；两者都只改变 `L_pub` 中是否含 `n`，
不改变 (A-RO) 的结构。

| 制式 | `n` 在公开值？ | 一次求值能测什么 | 界 | PV-2 |
|---|---|---|---|---|
| `n` 公开 | 是 | 一个 `T` 候选（`(n,t)`） | `q·Guess(T∣Z)+negl = q·2^{-k_T}+negl` | ✅ |
| `n` 保密 | 否 | 必须同时猜 `n` 与 `T` | `(1+q·2^{-f})·Guess(T∣Z)+negl`，`f=\|n\|` | ❌（指定验证者） |

`n` 保密时，只有选择 `n` 的接收方（和出证方）能重算 `b`，第三方无法核对
挑战绑定；这是**用 PV-2 换隐藏**，与命题 A.2 的带密钥 `β` 同构。松弛写法
`2^{-k_T}+q·2^{-f}` 由紧式用 `2^{-k_T}≤1` 放松得到，成立但更松。

#### 4.1.2 有损公开 `β` 的兜底

对**任意**公开确定 `β`（不假设 guess-tight），正确的界落在原像类上：
```
Pr[A^β(Z,β(T))=T]  ≤  Guess(T | Z, β(T))  ≜  E_y[ max_t Pr[T=t | Z,β(T)=y] ]。
```
它可能等于 1（`β=id`、`β=encode(T)`），也可能很小（难逆单射）。`q·Guess`
不是对任意 `β` 的定理；`β=id` 的反例是这条结构假设不可省的证明。

**证明草图**：对 A.1，固定 `z`，按「第一次命中 `X` 的查询」分解；在
`¬E_{<i}` 上用 Bayes/联合概率（不能直接写 `Pr[q_i=X|z]≤μ(z)`），每次查询
贡献 `≤μ(z)`；对 `z` 取期望并用 `E_z[μ(z)]=Guess(X|Z)` 得 `q·2^{-k}`。
对 A.2，没有 `β_s` oracle 时 `b` 在 ROM 下与 `X` 独立，最优策略是先验众数；
每次枚举还要猜中 `s`（`2^{-κ}`），多项式 `q` 下进 `negl(κ)`。对 A.3，逐条
排除：binding + PV-2 ⇒ A.1 给出隐藏需 `k_X` 足够；binding + hiding ⇒ `β`
必须带密钥 ⇒ PV-2 失败；hiding + PV-2 但无 binding 的方案不钉住 `X`，对合规
没有意义。完整证明见
[`proofs/theorem-a-b.md`](proofs/theorem-a-b.md) §2。

### 4.2 响应侧实例

`b = H(pop-bind-v1 ‖ u32be(|n|) ‖ n ‖ T)`，`n` 公开。

- `k_T ≈ 0`（贪心/低温解码 + 已知 prompt/模型）⇒ 重执行恢复 `T`，与证明系统无关；
- 要隐藏 `T`，只能让 `n` 保密（指定验证者）或让 `T` 高熵；前者牺牲 public verifiability。
- 这与现有 `security-model.md` §4.5 的 Corollary `reexec` 一致，但现在是三难的一个面。

### 4.3 策略侧实例（**新增**）

`policy_hash = H(canonical(π))`，`π` 是 witness，哈希公开。

- 策略空间并不大：8 类规则、参数范围有限、3–8 条规则；对手可以**枚举候选策略并匹配哈希**。
- 所以「π 是 witness ⇒ 策略已隐藏」**不成立**：关闭的是文本，不是哈希。
- 要让策略侧同时拿到 binding 与 hiding，必须把 `policy_hash` 换成**带秘密盐的承诺**：
  ```
  h_π = H( "pop-policy-commit-v1" ‖ canonical(π) ‖ policy_nonce )
  policy_nonce ← {0,1}^128，随策略包发行，但不进证书公开值
  ```
  这就是定理 D 的构造；它把 public verifiability 交给 P-PP 的签发权威
  （权威持有盐，可开示；验证者不能枚举）。
- **两个通道要分开说**：
  - **公开值通道**：`policy_hash` 本身可被枚举。加盐可以关闭它。
  - **证明工件通道**：SP1 `core` 的证明工件不隐藏见证，`π` 仍可能从 trace 泄露。
    只有 `groth16/plonk` 的 witness-hiding 才能关闭它（`sp1-zk-audit.md` §2–§3）。
  - **重执行通道**：与证明系统无关；对策略侧，如果对手知道部署上下文与策略库，
    `k_π` 可能很低——这正是盐要解决的问题。

> **这就是本框架最重要的新结论**：策略隐藏不是一个独立的新原语，而是**响应侧
> 同一个三难在 `X=π` 上的实例**。P-PP 不是补丁，是三难里「选择 public
> verifiability 换 binding + hiding」的那条腿。

## 5. 定理 B：泄漏剖面（统一 T1）

### 5.1 陈述

对任意证书方案与泄漏剖面 `L=(L_pub,L_proof,L_side)`，任意 `q≥1` 且可对 `β`
求值至多 `q` 次的对手（最终输出计入一次求值）：
```
Pr[ A^β(V) = X ]  ≤  q · Guess(X | L_pub, L_proof, L_side) + negl(λ)
                    = q · 2^{-k_X} + negl(λ)。
```
**定理陈述中不出现 `q·2^{-λ}`。** 旧 T1-H 里的这一项只在“获胜条件改为与
`β` 一致”且 `q` 无界时才可解释；本框架采用**精确恢复**（`X'=X`）并把最终输出
计入 `q`，该项不再是隐藏界的一部分。若审稿人要求与旧式对齐，可加一句：
“在一致性获胜变体中另加 `q·2^{-λ}`，且仅当 `q` 非多项式时不可吸收。”

> **字面版是平凡的**：若 `A` 没有 `β` oracle，`A(V)` 是 `V` 的函数，
> `Pr[A(V)=X]≤Guess(X|V)`。定理的价值在 `Guess` 的分解与三个 regime，
> 不在不等式本身；`q≥1` 保证 `q·Guess≥Guess`。

### 5.2 三个 regime（补 `n` 公开 / 保密）

| 证明档 / 场景 | `L_proof` | 结果 |
|---|---|---|
| `groth16` / `plonk`（witness-hiding） | `⊥` | 退化为公开值界 `q·2^{-k}` |
| `core` / `compressed`（非 ZK） | trace / `main_commitment` / `opened_values` | 界可到 1：证明工件本身泄露见证 |
| 重执行（任何档） | `L_side = (prompt, model, decoding)` | `k≈0`，与证明系统无关 |
| `n` 公开（请求制式） | 任意 | `q·2^{-k_T}`（`L_pub` 含 `b` 与 `n`） |
| `n` 保密（指定验证者） | 任意 | `(1+q·2^{-f})·2^{-k_T}`（`L_pub` 不含 `n`；PV-2 丢失） |

> 现有 T1 是 `L_proof=⊥` 的推论；`sp1-zk-audit.md` §3 的「证明工件不泄露见证 ❌」
> 是 `L_proof=trace` 的实例；`Corollary reexec` 是 `L_side` 的实例；最后两行是
> 请求制式的两种 `n` 可见性。**一条定理，三个 regime（`n` 两制式）**。

### 5.3 证明债（A1 收口）

- `q·2^{-λ}`：**已删除**，不再出现在任何定理陈述里（见 §5.1）。
- `q` 是**对 β 的求值次数**，不是时间；对手在时间上无界。论文必须写清。
- `n` 保密的紧界是 `(1+q·2^{-|n|})·2^{-k}`；框架旧版写的 `2^{-k}+q·2^{-|n|}`
  是它的松弛上界（成立但更松）。两种情形已在上表分列。
- 所有界是 ROM/heuristic；SHA-256 实例化损失进 `negl(λ)`。

## 6. 定理 C：交付绑定（统一 T3；`G_rep` vs `G_del`）

### 6.1 两个游戏与陈述

**`G_rep`（重放接受）**：对手 `O` 在见到 `r` 前预置已接受 transcript 集 `S`；
`r←N` 后 `U` 接受当且仅当 `Verify(cert,r)=1`（不要求交付工件与所证工件一致）。
这就是 T3′ 的游戏。

**`G_del`（divergent delivery，框架 D3）**：与 `G_rep` 相同，但 `O` 获胜还需
`T_U≠T_V`，其中 `T_V` 是 `cert` 所证工件（D1+D2 下由 `(cert,r)` 唯一确定）。

**引理 C.1（`G_rep` 的重放界）**：若 `S` 在见 `r` 前固定且每个
`|A(cert)|≤c`，则
```
Pr[U 接受] ≤ Σ_{cert∈S}|A(cert)|/2^f ≤ |S|·c·2^{-f}。
```
**`|S|·c·2^{-f}` 界的是 `G_rep` 的接受概率**，不是 `G_del` 的 divergence 概率。

**引理 C.2（`G_del` 的新鲜证书 divergence）**：在 D1、D2、B-bind 下，若证书在
见到 `r` 后新出且 `U` 接受，则 `Pr[T_U≠T_V]≤negl(λ)`。

**定理 C**：在 D1、D2、B-bind 下，对任意 PPT `O`，
```
Adv_del(O) ≤ |S|·c·2^{-f} + negl(λ)。
```
**读法**：第一项来自“来自 `S` 的重放接受”（引理 C.1），第二项来自“新出证书
的 binding 失败”（引理 C.2）。在 D2 下，`G_del` 的 divergence 本身是 `negl`；
`|S|·c·2^{-f}` 不是 divergence 的逐点界。

### 6.2 `f=0` 的三种读法（不要混用）

| 游戏 | 胜负事件 | `f=0` 优势 | 依据 |
|---|---|---|---|
| `G_rep` | `U` 接受 | **1** | `S` 中任一张证书永久覆盖 `r₀` |
| `G_del` + D1/D2/B-bind | 接受且 `T_V≠T_U` | `negl(λ)` | 引理 C.2；divergence 仍需碰撞 |
| `G_del^¬bind`（去掉 D2/B-bind） | 接受且 `T_V≠T_U` | **1** | 非绑定 `B` 可把任意 `T_U` 配到 `b(cert)` |

所以“`f=0` 时优势 1”属于 `G_rep`（或非绑定 `B` 的反例），**不属于 `G_del`+D2**。
论文若写“`f=0` ⇒ 交付绑定优势 1”，必须把胜负定义为重放接受，或明确 `B` 不绑定。

### 6.3 紧致性与分离

- **`G_rep` 紧**：接收方 nonce 协议（`c=1`，每 `r` 只接受一张证书）达到
  `|S|·2^{-f}`；挑战集两两不交时并界取等。
- **`c>1` 紧**：每张证书覆盖恰好 `c` 个挑战且互不相交时，接受概率达到
  `|S|·c·2^{-f}`（有意义的 regime 是 `c·|S|≤2^f`）。
- **`G_del` 在 D2 下不紧**：divergence 实际为 `negl`，上界成立但不是逐点紧；
  在 `G_del^¬bind` 下整体紧。
- **分离（`f=0`）**：在 stateless 公开验证、无外部机制的模型里，“公开可验证 +
  对接收方防重放 + 无接收方参与”不能同时成立；对手原样重放旧证书即可。
  有状态撤销表/可信时钟/硬件可绕开，故分离不是“任何系统都不可能”。

### 6.4 与现有 T3 的关系

现有 T3 是 `c=1`、`f>0` 的 `G_rep` 分支；本定理补上 `c>1` 的乘性损失、
`G_del` 的 divergence 分析、以及 `f=0` 的分离。实验见 `plan-bhv.md` 的 E5。
完整游戏、证明与反例见 [`proofs/theorem-c-e-f.md`](proofs/theorem-c-e-f.md) §1。

## 7. 定理 D：策略隐私与带盐承诺

### 7.1 D-privacy 的充分条件与定量陈述

游戏与优势见 D5：对手 `A` 输出 `(π₀,π₁,T,n,aux)`，**固定同一条 `T` 与同一个
`n`**（或要求 public T-view 相同），`D(π₀)=D(π₁)`、`R(π₀,T)=R(π₁,T)`；
挑战者采样 `b`，把 `View_b=(L_pub,L_proof,L_side)` 交给 `A`；
`Adv_{CS,D}(A,λ)=|2·Pr[b'=b]−1|`。

若

1. **C1（公开值模拟）**：存在 PPT `S_rest`，使除承诺外的公开值
   `L_rest(π,T,n)≈_c S_rest(pp,h_π,D(π),pub_T,n)`；
2. **C2（witness-hiding）**：存在 PPT `S_proof`，只取公开陈述
   `Stmt=(h_π,L_rest)`，使 `S_proof(Stmt)≈_c L_proof(π,T,n)`；
3. **C3（D-hiding commitment）**：对 `D(π₀)=D(π₁)`，
   `(pp,h_{π₀})≈_c(pp,h_{π₁})`；

则方案是 `D-private` 的，且定量地
```
Adv_{CS,D}(A,λ) ≤ O(ε_pub + ε_wh + ε_com)
```
（五主混合 + 两子混合给出常数 `≤5`）。

**证明草图**：H0 是 `π₀` 的真实视图；依次用 C2 换证明、C1 换其余公开值、
C3 换承诺、C1/C2 反向走回 `π₁`，得到 H5。每步最多一个模拟/隐藏误差。
完整混合与常数见 [`proofs/theorem-d-g.md`](proofs/theorem-d-g.md) §5。

> **固定 `T` 是游戏的一部分，不是可选澄清**：`b=B(n,T)` 是公开值，
> `T₀≠T₁` 时验证者一次重算即可区分；那属于响应侧 T1，不属于策略隐私。

### 7.2 带盐承诺构造（已落地原型）

```
policy_nonce  ← {0,1}^128            # 权威生成，随策略包发行
h_π = SHA256( canonical(π, policy_nonce) )
```
其中 `canonical(π,s)` 是代码的规范 JSON 字节串，`policy_nonce` 作为显式字段
参与键排序（不是字符串拼接）；论文附录应使用代码的精确字节串。

- `policy_nonce` 进入 `ConstraintSpec` 的规范字节，因此进入电路公开的 `policy_hash`；
- 它**不进**证书载荷的 `policy.id/version`，所以验证者看不到；
- 权威在 P-PP 里登记/签名 `h_π`；审计时权威开示 `(π, policy_nonce)`，验证者重算 `h_π`；
- 对手没有 `policy_nonce`，枚举空间乘以 `2^128`；即使策略在候选集里也匹配不上。

### 7.3 当前实现的缺口（必须写进论文）

| 通道 | 当前实现 | 加盐后 | 备注 |
|---|---|---|---|
| 公开值 `policy_hash` | ❌ 可枚举（策略空间小） | ✅ 不可枚举 | 本原型已覆盖 |
| 证明工件 `core` | ❌ trace 可能泄露 `π` | ❌ 仍泄露 | 需 `groth16/plonk`（E1，`[CLOUD]`） |
| 规则名 / `delegated` | ❌ 泄露策略结构 | ⚠️ 取决于披露层级 | 需 E4（L0/L1/L2） |
| 重执行 / 部署上下文 | ❌ `k_π` 可能很低 | ⚠️ 盐只保护哈希，不保护行为 | 需 E4 的推断攻击量化 |

> **不要把「加盐」写成「策略隐私已解决」。** 它只关闭公开值通道；证明工件通道
> 与披露层级通道是另外两条债，分别在 E1 与 E4 里还。

### 7.4 实验对应

- **E4a 枚举攻击**：对无盐 `policy_hash` 枚举候选策略并恢复；对有盐承诺做同样枚举，恢复失败。
- **E4b 披露层级**：L0（规则名）/ L1（类别 + 数量）/ L2（仅承诺）的推断准确率与审计效用。
- **E1 证明工件探针**：`core` vs `groth16` 的 trace/明文泄露。

## 8. 定理 E：组合的必要条件

### 8.1 陈述

若

1. `CS_policy` 与 `CS_infer` 都健全；
2. 两半绑到**同一个**新鲜 `n`；
3. 两半说的是**同一条** `T`（验证方现场重算 `response_binding`）；
4. `CS_infer` 绑到**用户提交的 `x_U`**；
5. 策略半 `delegated` 为空（或陪伴证明被合取）；

则复合证书推出 `∃T: R(π,T) ∧ T=M(x_U) ∧ b=B(n,T)`。

### 8.2 缺一条会怎样（反例）

| 缺的条件 | 反例 | 结论 |
|---|---|---|
| 不同 `n` | 两半各用各的 nonce | 不能确定是同一条 `T`；`T_policy ≠ T_infer` 也验得过 |
| 未绑 `x_U` | 推理半只证 `∃x` | 只说明「存在某个输入」，不是用户那条 |
| `delegated` 非空 | 语义规则被委托 | 只证「被委托了」，不是「满足了」 |
| 未绑 `T` | 推理半输出 `T'`，策略半判 `T` | 两半各说各话 |
| 两半不健全 | 策略半接受 `T⊭π` 的伪造证明 | 合取只保证「两半都说了它们说的话」，不保证「话是真的」；误差 `Adv_sound` 必须显式 |

> **当前实现的弱形式（open，不在 A1 修复）**：`verify_composite` 的
> `input_binding` 目前由 `derive(T_U)` 重算，而不是用户提交的 `x_U`；因此
> 实现只推出 `∃x: x=derive(T_U) ∧ T_U=M(x)`，**没有**推出 `T_U=M(x_U)`。
> 在 `x_U`（或其承诺）进入公开值并由验证方重算之前，论文只能写弱形式；
> 这对应证明债 E-1，属实现/后续工作，A1 只做理论收口，不实现它。

> 这就是论文 §7.5 的「组合本身不闭合缺口」的精确版本；实验见 E6。

## 9. 定理 F：签发完整性

### 9.1 不可能性

没有外部机制强制签发时，任何方案都无法对「运营方选择不签发」提供
issuance completeness：对手什么都不做即获胜。这不是实现的缺陷，是问题的边界。

### 9.2 充分性（三个前提必须同时写出）

若运营方在交付前必须把证书摘要追加到**只追加透明日志**，验证者检查包含证明，
则 completeness 在日志假设（只追加、可公开读、树头签名不可伪造）下成立。
但它**不是无条件结论**，依赖三条外部前提：

- **F-1（外部义务，F-O）**：运营方在交付前必须追加日志。这不是密码学结论；
  没有它，§9.1 的不可能性适用。若验证者强制要求包含证明，跳过会当场失败；
  否则只能事后由审计发现。
- **F-3（日志条目绑定被交付的 `T`）**：只记 `H(cert)` 不够；条目必须含
  `B(n,T)` 或交付回执（例如接收方签名的 `H(T)`），否则运营方可以记一张
  “另一条 `T`”的证书却交付另一条。
- **F-4（抽样框是“交付”而非“日志”）**：抽样审计的检出概率为
  `1-(1-p)^m`（`p` 采样率，`m` 独立可检违规数），前提是样本框包含**被交付的
  工件**。只抽日志时，withholding 对手根本不进样本，检出率为 0。独立性、
  命中即检出、检出不等于阻止，都是模型前提。

> 这把论文 §7.4 的 “open problem” 变成一对「不可能 / 条件充分 / 检出曲线」
> 结果；实验见 E10。完整证明与反例见
> [`proofs/theorem-c-e-f.md`](proofs/theorem-c-e-f.md) §3。

## 14. 哪些是新的、哪些是标准的

**标准（必须引用，不要包装成新定理）**：

- 猜测概率 / 最小熵界 `q·2^{-k}`（Dodis 等）；
- ROM 下的哈希隐藏论证；
- 重放/新鲜性的 union bound；
- 透明日志的包含证明与抽样检出概率；
- Thompson NFA / Pike VM 的标准构造。

**本框架主张的新意**：

1. 把响应、请求、**策略**三个面放进同一个 BHV 三难；
2. 策略侧的实例：`policy_hash` 是公开可枚举的绑定，因而需要带盐承诺；
3. D-privacy 的定义与「披露层级」的构造方向；
4. 组合的必要条件（定理 E）与签发的「不可能/可能」对（定理 F）；
5. 泄漏剖面 `L=(L_pub,L_proof,L_side)` 把 `core` / `groth16` / 重执行三种 regime
   收进一个定理。

> 论文的贡献陈述应写成「**框架 + 三难 + 策略侧结果 + 测量**」，
> 而不是「一个新的猜测界」。这样既诚实，也经得起审稿人问「这跟标准界有什么不同」。
